# V5 Engine — Спека интерактивного слоя

> **Что это.** Карта того, как прокачать v5-движок из «рендерит карточки» в «продаваемый разработчикам генеративный UI»: интерактивные примитивы (фильтры, тоглы, корзина, лайки, поля ввода, кнопки-на-ресурсы) + сцена/навигация + канвас v9. Документ grounded в реальном коде (file:line проверены агентами 2026-06-03), честен про дыры. Читается сверху вниз; в конце — самый маленький первый шаг и список «мелочей».
>
> Источник истины по тому, что СЕЙЧАС работает в движке — этот файл + `docs/v5-known-gaps.md`.

## 0. Одна мысль, которая всё разблокирует

Движок отдаёт браузеру **самоописывающийся JSON (scene-graph)**. Браузер тупой — он никогда не решает, *что значит* действие. Каждый интерактивный узел **несёт свой контракт действия прямо в себе**:

```json
{ "type":"text", "wrapper":"button", "content":"+",
  "action": { "kind":"cart_add", "entity":{"type":"product","id":"p-123"} } }
```

Виджет видит `action`, постит его на сервер, сервер применяет к состоянию сессии. Это **уже работает** для `like/unlike/cart_add/cart_remove`. Значит «сделать интерактив» = три вещи:

1. **Расширить словарь узлов** — к `frame/text/image/group` добавить `input/toggle/slider/select/chip`.
2. **Расширить закрытый список `kind`** (`domain/user_action.go`) + дописать парный обработчик.
3. **Для каждого действия решить: детерминированное или генеративное** (раздел 2 — это главный рычаг).

Твой вопрос «4 формы на экране, как API поймёт что они есть» растворяется: каждый `input`-узел несёт свой `formId`+`field` в `action`. Виджет на сабмите собирает все узлы с нужным `formId` и постит `{formId, fields:{...}}`. **Сервер не угадывает формы — узлы И ЕСТЬ реестр.**

## 1. Как движок работает СЕГОДНЯ (правда)

### Рендер-контракт
- Движок эмитит `Document {version:"2.10", themes, variables, children:[Node]}`.
- **Рендерятся 4 типа узлов:** `frame` (флекс-контейнер), `text` (с `format`+`wrapper`), `image`, `group`. (`engine/node_types.go:8-32` — там в словаре есть ещё 9 типов из порта v9: rectangle/ellipse/line/… — у них **нет фронтенд-рендерера**.)
- **Биндинг данных — free-form:** узел с `fieldBinding:"price"` читает `entity["price"]` из `data[dataIndex]`. Никакого фиксированного словаря (`engine/binding.go:59-145`).
- Пайплайн рендера: `Materialise(preset) → ApplyOps → ExpandReplicates → ResolveAndInline → BindData → InjectDefaultActions` (`tools/tool_visual_assembly.go`).
- `InjectDefaultActions` (`engine/inject_actions.go:60-176`) находит пустой фрейм `id:"actions"` и **автоматически** вставляет 2 кнопки: ♥ like и + cart_add. Это и есть твой образец паттерна — всё новое копирует его.

### Действия (закрытый словарь — `domain/user_action.go:13-71`)
9 видов:
- **Бэкенд (4):** `like / unlike / cart_add / cart_remove` → `POST /api/v1/actions` (`handlers/handler_action.go:48-108`).
- **Фронтенд (5):** `drill_detail / back / open_category / external_link / search` → диспатч в `renderer/actionDispatch.js`.

### Состояние сессии (Postgres — `domain/state.go:88-102`, таблица `v5_chat_session_state`)
Переживает между ходами: `current_data` (товары), `current_meta`, `current_template` (scene-graph), `view` + `view_stack` (для back), `actions` (LikedIds + CartItems), `conversation_history`. Каждая запись зоны атомарна (зона + дельта в одной транзакции).

### Фасеты (источник автофильтров — `postgres_catalog.go:503-726`)
`BuildCatalogDigest` детерминированным SQL считает `SharedFilters[]` (бренды, product_form, skin_type, …), дерево категорий, топ-бренды. **Важно:** это считается ОДИН раз в промпт Agent1, **не персистится** в сессии и **не виден** Agent2.

### Сцена / пререндер (`usecases/prefetch.go`, `handlers/handler_navigation.go`)
После рендера пайплайн читает `__presetInUse`, смотрит **захардкоженную** карту смежности (`engine/presets/adjacency.go:22-33`: `product_card→product_detail`), и для каждого товара пререндерит шаблон детали (без BindData) в `prefetch`. Клик по карточке → мгновенный оптимистичный рендер из prefetch + фоновая синхронизация через `/navigation/expand`.

## 2. Главный рычаг: детерминированное vs генеративное

Дели ВСЕ взаимодействия на два класса. Это решает цену и скорость.

| Класс | Что | LLM? | Путь |
|---|---|---|---|
| **Детерминированное** | фильтр, тогл, сортировка, пагинация, лайк, корзина, drill/back, сабмит формы (если только пишет в зону/сайд-эффект) | ❌ нет | чистый Go меняет состояние → возвращает **патч документа**, ~0 токенов, мгновенно |
| **Генеративное** | новый запрос словами; данные, которых нет в `current_data`; новый layout, который текущий пресет не выражает | ✅ да | перезапуск пайплайна Agent1+Agent2, ~250мс+, токены |

**Дыра прямо сейчас:** отфильтровать 50 загруженных диванов до «только COSRX» — это фильтр массива на 1мс, но сегодня это стоит полного хода Agent1+Agent2, потому что добраться можно только через чат. **Перенос частых кликов на детерминированный путь = 90% действий не трогают LLM.** Вот что делает генеративный UI дешёвым и быстрым настолько, чтобы ощущаться нативным. Это и продаёшь.

## 3. Round-trip протокол

Образец (фильтр-чип, детерминированно):

```
КЛИК (фронт)                       POST /api/v1/...           СЕРВЕР
chip.action =                  →   { sessionId,           →   GetState → мутировать состояние
 {kind:"filter_apply",              kind:"filter_apply",       (отфильтровать current_data)
  params:{facet:"brand",            params:{...} }             → пере-Materialise текущий пресет
          value:"COSRX"}}                                      → UpdateTemplate
                                   ←  { success:true,       ←  вернуть патч документа
onUpdateDocument(resp.document)        document:{...} }
(мгновенный перерендер,
 actionDispatch.js:101 — сеттер уже подключён)
```

**Ответ на твой вопрос про формы.** Сервер НЕ ищет формы. Каждый `input` несёт `action.params.formId` + `field`. Кнопка сабмита несёт тот же `formId`. Виджет на клике обходит документ, собирает все `input` с этим `formId`, постит:
```json
POST /api/v1/actions
{ "sessionId":"…", "kind":"form_submit",
  "params":{ "formId":"signup", "fields":{ "email":"a@b.com", "name":"Vlad" } } }
```
4 формы = 4 разных `formId`. Сервер обрабатывает тот, что пришёл. Реестр не нужен — **узлы и есть реестр**.

## 5. Панель фильтров (твоя точка №1)

**Сегодня:** панели фильтров НЕТ вообще. Раскладка виджета статична — `.kw-display` (scene-graph, flex:1) + `.kw-chat` (360px справа, только чат). Фильтров на экране ноль (`WidgetApp.jsx:150-175`, `chat/ChatPanel.jsx:40-56`, `widget.css:50-92`).

**Не только чипы.** Кроме бренд-чипов нужны:
- **Цена** — слайдер min/max (бэкенд `tool_state_filter.go:78-82` уже фильтрует цену в копейках; фронт→копейки на отправке).
- **Мультиселект** — группа чекбоксов (цвет, размер, in_stock).
- **Сорт** — дропдаун (relevance / price_asc / price_desc / rating).

**Две стратегии (выбрать):**
- **Вариант A (простой MVP, рекомендуется для старта):** фильтры живут в **сайдбаре ChatPanel как раскрывающийся drawer**, НЕ в scene-graph. Не нужны новые типы узлов.
  - `ChatPanel.jsx`: стейт `[filterOpen,setFilterOpen]` + кнопка-тогл + блок `.kw-filter-panel` под историей чата.
  - `widget.css`: `.kw-filter-panel{ max-height:0; overflow:hidden; transition:max-height 200ms } .kw-filter-panel[data-open='true']{ max-height:500px; overflow-y:auto }` — закрыта по умолчанию, раскрывается на тогл (ровно твоё «пусть раскрывается частично»).
- **Вариант B (гибче, позже):** фильтры — узлы прямо в scene-graph (`slider/checkbox/select`). Требует новых типов узлов + рендереров (`renderer/nodes/Slider.jsx`, `Checkbox.jsx`, `Select.jsx` + ветки в `NodeRenderer.jsx:18-37`). Это даёт Agent2 решать, КУДА класть фильтры, но дороже.

**Нужно для обоих:** новый `kind` `filter_apply/filter_reset/sort_by` в `user_action.go`; обработчик; и **обогатить `DigestSharedFilter`** (`catalog_digest.go:36-40`) полем `type:"enum|range|sort"` + `min/max` для цены — иначе фронт не знает, чип это или слайдер.

## 6. Кнопки на внешние ресурсы (твоя точка №2)

**Где сейчас берётся цель кнопки.** Целиком инлайн в `action.params` — **управлять негде**. `external_link` читает `params.url` → `window.open(...)`; `open_category` читает `params.categoryId` → новый ход поиска (`actionDispatch.js:137-148`). URL туда попадает либо захардкожен в пресете, либо его собирает Agent2. Отдельной таблицы/конфига кнопок нет; всё лежит в `current_template` JSONB.

**Три способа управлять+хранить+биндить (по возрастанию зрелости):**

- **A — метаданные в пресете (проще всего, v5-only):** добавить в пресет массив `buttons`, например `{id, label, kind:"external_link", paramBinding:"external_url"}`. `inject_actions.go:147-164` читает это и при `paramBinding` берёт значение из `data[i].external_url` → `params.url`. Менять URL = перепубликовать пресет.
- **B — таблица конфигов тенанта (продакшен):** `v5_action_config(tenant_id, key, action_kind, params JSONB)`. Пресет ссылается ключом (`{id:"cta", config_key:"view_all_url"}`), движок подставляет на рендере. Динамично, без перепубликации. Нужен admin-эндпоинт `POST /api/v1/admin/.../action-config`.
- **C — канвас v9 (будущее):** «Buttons»-панель в канвасе → пишет в таблицу → v5 читает на рендере. Визуально, без кода (см. раздел 8).

**Цель кнопки бывает трёх видов** — поддержать все: статичная (`params.url`), привязанная к полю (`paramBinding:"externalUrl"` — у каждого товара своя ссылка), по ключу-конфигу (`config_key:"view_all_url"`).

**Рекомендация:** сейчас — Вариант A (ноль схемы, ноль эндпоинтов), потом B как escape-hatch. Якорь старта: `engine/inject_actions.go:147-164`, структуру пресета — `domain/preset.go:27-47`.

## 7. Сцена / граф навигации / пререндер (твоя точка №3)

**Как работает сегодня (частично):** «рендерим ровно что попросил + пререндерим соседний ход». После Agent2 пайплайн (`pipeline_execute.go:156-162`) по `__presetInUse` смотрит карту смежности и пререндерит шаблон детали для каждого товара в `prefetch` (намеренно **без BindData** — биндинг происходит на фронте в момент клика, чтоб один шаблон годился под N товаров). Клик → мгновенный рендер из prefetch + фон-синхронизация `/navigation/expand`. Это **работает** для системных пресетов.

**Что сломано / недоделано:**
1. **Back-кнопка сломана на фронте** — серверный `/navigation/back` работает, но `WidgetApp.jsx:78` сбрасывает `canGoBack=false` после каждого хода; глубина стека с сервера на фронт не синкается (`v5-known-gaps.md:144`).
2. **Смежность захардкожена** (`adjacency.go:22-27`, 4 строки) — тенант не может задать свой drill-таргет без правки кода.
3. **Пререндерится только переход в деталь** — одна исходящая грань; нельзя пререндерить несколько соседних ходов.
4. **Тихая обработка ошибок prefetch** (`prefetch.go:76-99`) — падает в debug-лог, нет видимости.
5. **Дублирование роутинга** — `AdjacentPreset()` зовётся и в `handler_navigation.go:110`, и в `prefetch.go:71`.

**Как чинить+качать (по приоритету):**
- **P1 — смежность из БД:** `ALTER v5_presets ADD metadata JSONB` (`{"drillTarget":"…"}`); `adjacency.go` читает метадату пресета, фолбэк на системную карту. ~50 строк. **Это же разблокирует канвас** (тенант задаёт переходы визуально).
- **P2 — починить back:** добавить `stackSize` в ответы навигации+пайплайна; на фронте `canGoBack=(stackSize>0)`, убрать сброс на :78. ~15 строк.
- **P3 — видимость ошибок prefetch** (debug→info/warn с именами пресетов).
- **P4 — e2e-тест дрилла** (что пререндеренный шаблон реально биндится).
- **P5 — консолидировать роутинг** в один `GetDrillTarget()`.
- **P6 (позже) — мульти-переходы:** `map[string][]string`, prefetch по имени грани.

> **Важно (не баг, а замысел):** BindData в prefetch пропущен НАМЕРЕННО — пререндерится *форма* шаблона, биндинг к сущности на фронте в момент клика, чтобы один шаблон переиспользовался под каждый клик. Не «чинить» это.

## 8. Канвас v9 (твоя точка №4)

**Что это.** `Keepstar_one_v9` — полноценный Figma-класс редактор: WebGL2-рендерер, Yoga-раскладка, 13 типов узлов, компоненты, undo/redo, CRUD документов в Postgres, AI-агент (`batch_design` DSL) который рисует/правит дизайн. Может **авторить и генерить** UI.

**Совместимость форматов — 99%.** v9 и v5 делят один node-модель (те же 13 базовых типов, `version:"2.10"`, та же форма Variables/Themes/Fills, та же система Ref-компонентов). v5 добавил только `NodeTypeImage` как runtime-хинт для биндинга картинок — этого в v9 нет (нужен конвертер на импорте). Планы: `docs/v9-canvas-integration-plan.md`.

**Что мешает использовать канвас как авторинг пресетов для v5:**
- **v5 preset_port — read-only** (`ports/preset_port.go:16-25`): есть `GetPublishedPreset/ListPublishedPresets`, но **нет CreatePreset/SaveDraft/Publish**. Таблицы `v5_presets`+`v5_preset_versions` созданы (`preset_migrations.go:18-52`), но writer-методов нет. **Канвасу некуда сохранять.**
- Канвас не вшит в admin (нет iframe-моста, JWT-проброса).
- Нет «golden round-trip» теста v9→v5 (что `id:"actions"` фрейм, image-узлы, $ref переживают рендер-пайплайн).

**Путь интеграции (фазы):**
- **P1 (4-6ч, гейтит всё):** write-эндпоинты в v5 (`CreatePreset/SaveDraftVersion/PublishPreset`). Разблокирует пресеты, написанные руками через curl ИЛИ экспортом из standalone-канваса (он уже работает на порту 5180). Образец — существующий admin KeepstarCanvas writer.
- **P2 (2-3ч):** редактируемая смежность (`v5_presets.metadata`, см. раздел 7 P1).
- **P3 (3-4ч):** golden round-trip тест (зафиксировать формат v9→v5 до кода канваса).
- **P4+ (после пилота):** вшить канвас в admin (vendor в `project_v9/`, переключить хранилище на общий Postgres, JWT-изоляция, iframe+PostMessage, BindingSection в инспекторе).

> **Канвас — НЕ блокер.** v5 гейтится на P1 (часы, переиспользуемо), не на вшитии канваса (недели). Пилот едет на пресетах, написанных руками или экспортом из standalone-v9.

## 9. Подводные камни (честно — из adversarial-проверки кода)

Наивный путь «просто добавь `kind` и верни `document`» НЕ полетит. Реальные предусловия:

1. **`/v1/actions` не умеет перерендеривать.** `ActionHandler` держит только `StatePort` (`handler_action.go:31-33`); для рендера нужны `PresetPort`+`ComponentPort`+тенант из контекста. → **Вешай фильтр/нав-действия на `NavigationHandler`** (у него уже всё есть и он уже рендерит, `handler_navigation.go:264`), а не на ActionHandler.
2. **Гард `entity required`** (`handler_action.go:70-73`) рубит любое бэкенд-действие без `entity` (400). `filter_apply`/`form_submit` без entity → 400. Надо ослабить (или жить на навигационном хендлере, где гарда нет).
3. **`matchProduct`** (`tool_state_filter.go:149`) знает только brand/category/price/rating/text — массивные фасеты (skin_type, concern, key_ingredients) **не матчит**; и функция приватная в пакете `tools` (вынести/экспортировать перед вызовом из `handlers`).
4. **Нет зоны Filters.** `state_filter` перезаписывает `current_data` отфильтрованным набором → база теряется, стек фильтров не пересобрать. Нужна зона `Filters` + хранить несфильтрованный базовый набор + миграция.
5. **Дайджест фасетов не достаёт до пути действий** (только строит промпт Agent1, не персистится). Для чипа с реальным значением — либо персистить дайджест, либо инжектить значения при рендере.
6. **Фронт:** новые типы (`input/slider/checkbox/select`) = новые case в `NodeRenderer.jsx:18-37` (сейчас неизвестный тип не рендерит ничего) + ветки в `wrapper.js:24-78` + form-store в `RenderContext`. Чип — мелочь; полноценный input/форма — мультифайловая стройка.

## 11. Самый маленький первый шаг

**Один бренд-чип, который сужает уже показанные товары без LLM.** Проводит весь round-trip на самом дешёвом примитиве; обходит 4 из 6 подводных камней:

1. Новый `kind:"filter"` — обрабатывать на **навигационном** хендлере (у него есть пресеты+компоненты+тенант, и нет гарда `entity`).
2. Фильтровать `state.Current.Data.Products` по бренду **на месте** (пока без зоны Filters — для пруфа потеря при ре-сёрче ок).
3. Бренд для чипа брать из товаров, что уже в сессии (самый частый), не из дайджеста.
4. Перерендер тем же путём, что `handler_navigation.go:264` (`Materialise→BindData→InjectDefaultActions`) по текущему пресету → `UpdateTemplate` → вернуть `document`.
5. Фронт: ветка `'chip'` в `wrapper.js` (копия ветки `button`) + `case 'filter'` в `actionDispatch.js` → `ctx.onUpdateDocument(resp.document)`.
6. Один чип захардкодить в пресет `product_grid` (или инжектнуть как `InjectDefaultActions`).

**Видимый результат:** ищешь «диваны» → 30 карточек + чип «HUIMO» → клик → сетка мгновенно сужается, ноль латентности LLM, ноль токенов.
