L2

Search projection — per-tenant срез (РЕАЛЬНО построен)

Денормализованный ранжирующий индекс на (tenant_id, master_variant_id). Несёт тексты + embedding + tsvector. Цена/сток/фото НЕ дублируются — V5 гидрирует их на чтении. Строится автоматически после apply.

catalog.merge_reports pre-inbox legacy ВСЁ ЕЩЁ ЖИВА
Целевой план помечал её под DROP, но в live-схеме она пока осталась. Не используется новым флоу — кандидат на снос.
Сквозной сценарий: «увлажняющая сыворотка» в чате тенанта (как СЕЙЧАС) V5 эмбеддит запрос (OpenAI 384) — если ключ есть; иначе FTS-only. Один fused-запрос к tenant_search_projection WHERE tenant_id=? : score = COALESCE(1−cosine,0) + COALESCE(ts_rank('simple', query),0), ORDER BY score DESC LIMIT N. Срез изолирован по тенанту. Гидрация: ранжированные variant_id → JOIN на products (price, stock_quantity, display_name, tenant_overrides) + master_products (brand, tier2) + master_variants (size/volume) + lateral на master_categories (имя категории). Никаких master_cosmetics/categories/stock. Render: карточка из domain.Product — косметик-поля (skin_type/product_form…) берутся из tier2, пайплайн/виджет не изменились. Apply нового тенанта сам строит projection-строки (с эмбеддингами) после BulkUpsertListing — слайс самоподдерживается.
