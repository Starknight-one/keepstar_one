Когда используется

  • Новые данные (Agent1 вызвал catalog_search или state_filter)

Snapshot Carry-Over

Перед пересборкой: извлекает locked кастомизации из старой Formation. После пересборки: накладывает обратно. Так "сделай цену красной" переживает следующий AUTO.

Что сохраняетсяЧто теряется
textStyle wrapper mediaStyle iconStyle format freestyle atoms grid columns grid rows formation mode widget size layout node config (gap, align) widget container styles atom ordering changes
Ключевое: Snapshot работает по rigidity: locked. Только атомы с locked сохраняются. Ops автоматически ставит locked на все модификации. Auto ставит locked только если юзер явно попросил.

Deltatool: visual_assembly, mode: auto, count: N
O

Update / Delete / Insert / Move по Tree ID или Field Name

Когда используется

  • "сделай цену крупнее" → update target:"price"

  • "перенеси бренд в теги" → move target:"brand" parent:"tags"
  • "5 колонок" → update target:"formation" props:{columns:5}

Wildcard Expansion

Agent2 шлёт одну операцию с field name (не ID). Движок раскрывает в N операций — по одной на виджет.

Вход:  {"op":"update", "target":"price", "props":{...}}

Раскрытие (23 виджета):
  {"op":"update", "target":"a-s0-w0-price", "props":{...}}
  {"op":"update", "target":"a-s0-w1-price", "props":{...}}
  ... × 23
Как определяется wildcardЛогика
TargetisTreeID(target) == false → ищет atoms с matching fieldName
Parent (insert/move)isTreeID(parent) == false → ищет layout nodes с matching Name
isTreeID(s)Начинается с a-/n- или длиннее 8 символов (UUID)
Dedup guard: если Agent2 шлёт и конкретный ID, и field name для того же виджета — дупликат отсеивается. Трекаем (widgetID, opType, fieldName).

Insert — подробнее

ПараметрЧто
parentКуда вставлять: node name ("root", "tags") или tree ID
afterПосле какого atom/node ID. Без after → в конец
refЛокальный алиас. Последующие ops могут юзать $ref
props.type"text", "image", "icon" (atom) или "row", "column", "flow" (layout node)
props.fieldNameData-bound: движок сам подставит значения из entity data
props.valueFreestyle: литеральное значение (текст, URL)

Проблема

Юзер делает OPS: "цену красную, добавь кнопку купить". Потом: "покажи шампуни" (новые данные → AUTO). Без snapshot все кастомизации теряются.

Решение: SnapshotCustomizations → ApplySnapshot

Prev Formation → SnapshotCustomizations → Snapshot → V2 Engine (fresh) → ApplySnapshot → Final Formation

Что snapshot захватывает

ДанныеУсловиеИсточник
FieldOverrides
textStyle, wrapper, mediaStyle, iconStyle, format		 rigidity == locked + fieldName != "" Первый виджет (все виджеты одной структуры)
FreestyleAtoms
полный atom + parent node name		 rigidity == locked + fieldName == "" Первый виджет
FormationOverrides
grid (cols, rows), mode, widget size		 Всегда (если заполнены) Formation + первый виджет

Как ApplySnapshot восстанавливает

ШагЧто
1Восстановить Grid (cols, rows) и Mode на Formation
2Восстановить WidgetSize на все виджеты
3Для каждого виджета: найти атомы по fieldName, восстановить overrides
4Для каждого виджета: добавить freestyle atoms, найти parent node по имени
5Вызвать WidgetV2ToLegacy + StampTreeIDs
Ограничение: Snapshot берёт только первый виджет как reference. Если у секционных формаций разные виджеты — кастомизации виджетов 2+ теряются. Freestyle atoms при восстановлении теряют позицию (всегда appended в конец parent'а).

if (sections?.length > 0) {
  // Рекурсия: каждая Section = мини-Formation

WidgetRenderer — критический gate

if (widget.template) {         // ← ОБЯЗАТЕЛЬНО для V2 пути
  renderTemplate(widget)       // → GenericCardV2Template
} else {
  // LEGACY FALLBACK: plain <span>{atom.value}</span>
  // Без стилей, без layout, без wrapper
}
Widget.Template обязателен! Без Template: "GenericCard" виджет рендерится как plain text. Auto mode ставит Template в Engine. Freestyle widgets в build mode тоже ставят Template.

GenericCardV2Template

Единый компонент для всех типов виджетов. Рендерит через LayoutTreeRenderer.

  • Принимает: atomsV2[], layout, size, direction, entityRef, states
  • LayoutTreeRenderer обходит LayoutNode дерево, рендерит flex-контейнеры
  • Для каждого AtomChild → AtomV2Renderer
