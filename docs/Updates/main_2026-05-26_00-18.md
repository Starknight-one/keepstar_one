# Search layer — tenant_search_projection + embeddings + V5 repoint — 2026-05-26

## Context
PIM tables are structurally done, but the **search** layer underneath was missing/broken,
which blocked exercising V5 on the new catalog:
- No per-tenant search slice; embeddings were generated only by the legacy `ImportUseCase`
  (not the V2 apply/seed path), used cosmetics-specific text, and `OPENAI_API_KEY` was unset
  (live: 991/1951 masters had vectors, variants 0/1951).
- V5's catalog reads (`catalogProductSelect`, `catalogVectorSelect`, **and** `BuildCatalogDigest`)
  JOINed `master_cosmetics`, `categories`, `stock` and selected `mp.category_id` — all dropped in
  Group D — so V5 search + the agent1 prompt-cache digest erred against the current schema.

Owner-approved scope (4 points + fix all broken V5 reads): projection table, builder, embedding
generation, V5 repoint. Embeddings via OpenAI key (owner provides). Out of scope: sibling grouping
(seed data has no groupable structure — Amazon 3000 unique parent_asin/0 groups, Sephora no parent
key), D6 vocab.

## Approach
Projection is a **ranking index only** (texts + embedding + tsv); V5 hydrates display fields from
canonical tables at read time, so a price change never forces a re-embed. Repointing V5 to the
projection simultaneously replaces its broken dropped-table queries.
