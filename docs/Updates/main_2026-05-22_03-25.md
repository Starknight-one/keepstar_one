## Context

The 0.9.4 milestone closed Group A (Sephora seed blockers) + B1
(discovery patches existing artifact). Next on the agreed roadmap was
B2 — schema drift detection: after each apply, automatically check
whether new fields appeared in the tenant's data that aren't covered
by the current mapping artifact, and classify each as a typo of an
existing key / an alias of an existing attribute / genuinely new.

Owner asked to **lay in a Redis-based message broker now**, even
though semaphore-bounded goroutines would have worked at current scale.
Reasoning: broker is useful for other async work coming up (V5 events,
audit fan-out, future follow-ups), and laying it now while the
integration is small is cheaper than retrofitting later. Worker pool
stays in admin backend for v1 — moves to a separate `pim_worker`
service later, alongside the PIM extraction milestone.

## What shipped

### Broker infrastructure (new, reusable across the project)

- **`internal/ports/broker_port.go`** — minimal `BrokerPort` interface
  with `Publish` / `Subscribe` / `Close`. Subscribe blocks per consumer,
  dispatches messages one at a time, ACKs on success, lets the broker's
  redelivery handle failures. Future swap to NATS / Postgres-based queue
  is a single-adapter change.
- **`internal/adapters/broker/redis_broker_adapter.go`** — Redis Streams
  impl using `github.com/redis/go-redis/v9`. One stream per topic
  (`stream:<topic>`), one consumer group per worker pool, named
  consumers per goroutine. `XAUTOCLAIM` background loop runs every 60s
  with 5-minute idle threshold to recover stuck messages from crashed
  workers.

Reconnection / DNS / pool config: defaults from `go-redis`. Local dev
uses `REDIS_URL=redis://localhost:6379`; Railway emits the URL
automatically when the Redis service is provisioned in the project.

### Schema drift usecase

- **`internal/usecases/schema_drift.go`** — orchestrator. Two entry
  points: `PublishJob(tenantID, applyRunID)` (called inline at the end
  of `ApplyForTenant`, fast — just `XADD`), and `Classify(ctx, tenantID,
  applyRunID)` (called by worker, does the heavy work).
- `Classify` loads the existing artifact, lists inbox fields, computes
  unmapped = inbox_fields − artifact_mapped_keys (capped at 20 per run),
  gathers `FieldStats` evidence per unmapped field, runs a deterministic
  `GuessFieldType`, calls the LLM classifier with one batched request,
  and upserts results into `catalog.schema_drift_findings`.
- **`internal/usecases/schema_drift_type_guess.go`** — deterministic
  helper. Five outputs: `numeric` (all samples parse as floats), `date`
  (regex against ISO / RFC3339-ish), `categorical` (≤50 distinct AND
  distinct/total ratio < 0.3), `text`, `unknown` (empty stats).

### Drift classifier (LLM adapter)

- **`internal/adapters/anthropic/drift_classifier_client.go`** — clones
  `EnrichmentClient` HTTP shape but targets `claude-sonnet-4-6` (per
  owner choice for accuracy on borderline alias/new calls). One-shot
  Messages API POST, no tools, JSON-only response. Defensive against
  hallucinated field names — filters response to fields that were
  actually asked about.
- System prompt spells out the three decisions (typo/alias/new), the
  allowed target prefixes (`master.<col>` | `cosmetics.<col>` |
  `tier3.<key>`), and a decision rubric with Levenshtein hint for
  typos.

### Persistence

- **Migration** in `catalog_migrations.go`: new table
  `catalog.schema_drift_findings` with UNIQUE
  `(tenant_id, apply_run_id, field_name)` for idempotent redelivery.
- **`internal/adapters/postgres/schema_drift_findings_adapter.go`** —
  `Upsert` / `List` / `Get` / `MarkApplied` / `MarkDismissed`. The
  `ON CONFLICT DO UPDATE` clause refreshes classification but doesn't
  override already-applied/dismissed status (curator's decision wins).

### Producer hook

- **`apply_v2.go`** — `AttachSchemaDrift(sd)` setter + `newDriftRunID()`
  helper. After the existing `actionLog.Log("apply", ...)` and before
  `return res, nil`, if `schemaDrift != nil` we publish a job. Failure
  is logged as a warning — apply still succeeds. Drift is opt-in via
  `cfg.HasRedis()`.

### Worker pool wiring

- **`cmd/server/main.go`** — extends the existing `bgCtx` + goroutine
  pattern (already used by `CronDailySourcePull`). When `cfg.HasRedis()`
  is true: construct `RedisBrokerAdapter`, attach `SchemaDriftUseCase`
  to `applyV2`, spawn `cfg.DriftWorkers` (default 5) goroutines each
  subscribed to the `drift_classify` stream as a unique consumer.
  `recover()` inside the handler catches panics so a buggy LLM-response
  parse can't kill a worker.
- Graceful shutdown: `bgCancel()` cascades through ctx; broker's
  `Close()` deferred at the goroutine startup site.

### Admin UI

- **`internal/handlers/handler_schema_drift.go`** — three endpoints:
  - `GET /admin/api/catalog/drift?status=classified` — list findings
    (tenant defaults to session, override via `tenant_id=` query for ops)
  - `POST /admin/api/catalog/drift/{id}/apply` — accept finding →
    triggers `discovery_v2.Discover(trigger="manual_drift_apply",
    payload=action)`, which uses B1's patch flow to amend the artifact
    in-place
  - `POST /admin/api/catalog/drift/{id}/dismiss` — reject finding
- **`project_admin/frontend/src/features/catalog/SchemaDriftPage.jsx`**
  — list view with Pending / Applied / Dismissed tabs. Each row shows
  field name, type guess, decision pill (warning / info / fresh —
  brand-blue + brand-orange palette, no purple), confidence, suggested
  action summary, stats line with sample values.
- Nav link in `DashboardLayout.jsx` under Catalog submenu (GitCompare
  icon).

### Config

- `internal/config/config.go` — new env vars: `REDIS_URL` (empty =
  drift disabled), `DRIFT_CLASSIFIER_MODEL` (default
  `claude-sonnet-4-6`), `DRIFT_WORKERS` (default 5). `HasRedis()`
  checker added alongside existing `HasDatabase()` / `HasEnrichment()`.
- New helper `getIntEnv()` for parsing the worker count.

## Tests

- **`schema_drift_type_guess_test.go`** — 9 cases covering all five
  outputs (numeric / date / categorical / text / unknown), including
  boundary ratio between categorical and text and the blank-sample
  carve-out for numeric.
- **`schema_drift_test.go`** — fake broker + 3 assertions on
  `PublishJob`: happy path, nil-broker no-op, broker-error
  propagation.

No integration test for the drift findings adapter this milestone —
covered by the producer-hook end-to-end story (apply triggers publish
which triggers worker which writes findings). Will add a dedicated
Postgres regression if redelivery semantics turn out to bite.
