# Legacy code purge — catalog v2

**Commit:** `62a2e36 chore(catalog-v2): remove legacy discovery/merge/junk/harvester code`
**Branch:** main
**Plan:** `~/.claude/plans/structured-discovering-lollipop.md` (Addendum: Legacy code purge)

## Context

After the 2026-05-14 ship the new 6-step catalog flow (inbox → discovery_v2 → apply_v2 → orchestrator) was live and smoke-tested at $0.044 / ~30s / 10/10 success. The 12 legacy usecase files and 3 CLI binaries remained on disk as a transitional fallback. They made the repo dishonest: a reader couldn't tell which path was active without tracing DI in main.go, and `ShopifyV2UseCase` silently fell back to the legacy harvester if `inboxIngester` was nil. Step 10 of the catalog rebuild plan was "delete legacy code". This commit executes it.

## Approach

1. Mapped every reference to the 12 legacy files via Explore agent (constructors, handlers, routes, CLI binaries, tests, ports/adapters).
2. Deleted source files in dependency order: tests → usecases → handlers → ports → adapters → CLI binaries.
3. Edited shopify_v2.go to require `inboxIngester` (panic-on-nil instead of silent legacy fallback), dropped the `HarvesterLite` interface + `harvester` field + `SetHarvester` method + `runInitialIngestLegacy` + the entire `DumpToStaging`/`dumpXxx`/`streamJSONLToStaging`/`countMenuItems` chain. Kept `runBulkProductsAndWait`, `bulkPullProductsAsInboxItems`, `productAccum`, `mergeChildrenIntoProduct`, `classifyChild` — all still used by the new flow.
4. Edited cmd/server/main.go to drop legacy DI blocks (harvesterLite, discoveryUC, mergeApplyUC, mergeCascade, curatorMergeHandler, junkHandler, shopifyV2Handler, shopifyStagingAdapter, mergeApplyTxAdapter, candidatesAdapter, masterVariantsAdapter, mappingArtifactAdapter, mergeReportsAdapter) + their HTTP routes (/dump-to-staging, /discover, /merge/*, /merge-reports, /admin/api/junk*).
5. Curator backend: removed orphan candidates/junk/merge DB methods from postgres.go, matching handler methods + routes, trimmed handler_merge.go down to just `HandleSyncNowV2`.
