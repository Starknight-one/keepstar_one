## Step 1 — protect POST /api/v1/pipeline (money leak)
The only public endpoint that triggers paid LLM calls had no auth, no rate
limit, no spend cap (CORS `*` is intentional for an embeddable widget). A bot
finding the widget URL = uncapped Anthropic spend, no alert.
- NEW `internal/handlers/pipeline_guard.go` — `PipelineGuard`: per-client-IP
  token-bucket rate limit (`PIPELINE_RATE_PER_MIN`, default 30/min, burst =
  rate) → 429; global daily USD spend ceiling (`PIPELINE_DAILY_USD_CAP`,
  default $10/day) accumulated from the real per-turn `LLMUsage.CostUSD` → 503,
  resets at UTC midnight. In-memory/process-local (correct for single-instance
  Railway; documented to move to a shared store if V5 scales out). nil guard
  and `<= 0` limits both disable. Bounded IP map with idle eviction.
- `handler_pipeline.go` — guard checked before body read; `RecordCost` after a
  successful turn. Also closed an info leak: the 500 path returned the raw
  `err.Error()` to the client; now logs server-side + returns a generic message.
- `config.go` (v5) — `PipelineRatePerMin` + `PipelineDailyUSDCap` env knobs.
- `main.go` (v5) — construct + inject the guard; log its config at boot.
- Tests `pipeline_guard_test.go` — rate limit + refill (injected clock), daily
  cap + UTC-day reset, disabled/nil safety, clientIP (XFF → RemoteAddr).
- Fixed a pre-existing dark file `handler_pipeline_live_test.go` (stale
  RegisterRoutes/NewPipelineHandler signatures); still dark — a third stale call
  (`NewCatalogSearchTool` missing embeddingPort) needs the embedding-port wired,
  left as a separate task (not chased).

## Step 2 — JWT_SECRET fail-closed (admin)
`config.go:76` fell back to the public default `keepstar-admin-secret-change-me`;
if `JWT_SECRET` were unset in prod, anyone could forge admin tokens.
- `config.go` (admin) — extracted the default to a const; added `IsProduction()`
  + `Validate()`: in production a missing/default secret returns an error.
- `main.go` (admin) — call `cfg.Validate()` after Load(); `log.Error` + exit on
  failure (same pattern as the DATABASE_URL check). Dev keeps the convenient
  default.
- Test `config_test.go` — dev-default OK; prod default/unset rejected; prod
  strong secret OK; `prod`/`PRODUCTION` aliases.

## Step 3 — fail-open the other catalog.* reads (v5)
Only `field_definitions` had a 42P01 (undefined_table) guard; a drop of any
other `catalog.*` table would 500 every tenant (field_definitions-class).
- Added the existing `isUndefinedTable` guard to the runtime data reads:
  `ListProducts` (count + main), `GetProduct` (→ not-found), `BuildCatalogDigest`
  (→ empty digest), `VectorSearch`, `SearchProjection`, `SampleFieldValues`
  (→ empty samples). Each degrades to empty + WARN instead of 500.
- `GetTenantBySlug` / `resolveTenantID` left LOUD on purpose — a missing
  `catalog.tenants` is catastrophic (no tenant can be served); failing open
  there would mask a fatal misconfig as "tenant not found".
- Test `undefined_table_test.go` — `isUndefinedTable` matches 42P01 (incl.
  wrapped), rejects other codes / plain / nil.

### Finding (DB-verified on flat-moon)
`SampleFieldValues` is **already broken** against the Group-D schema: it JOINs
the dropped `catalog.categories` and selects dropped columns
`mp.product_form/skin_type/concern/key_ingredients/category_id` (only `mp.tier2`
survives) → 42P01 at runtime. The data-derived `<fields>` enrichment has
therefore been silently empty (`FormatFieldsBlock` fail-opens at
fields_block.go:67). The Step-3 guard now degrades it cleanly + logs a WARN
(previously the error was swallowed, invisible). The proper fix — rewrite the
query to read `tier2` + the `master_categories` junction + `products.extra` — is
the phase-3 "genericize SampleFieldValues" engine task.

### Cron risk #1 downgraded (code + DB verified)
The 24h `NewCronDailySourcePull` is double-gated: env `KEEPSTAR_DAILY_SOURCE_PULL=1`
AND per-tenant `settings.dailySyncEnabled=true`. flat-moon: all 34 tenants have
it UNSET → the cron pulls 0 tenants → zero apply_v2/discovery/LLM spend today.
It's an inert latent foot-gun, not an active fire. (Audit's "no off-switch"
was overstated.)
