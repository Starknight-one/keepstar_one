Resolve raw free-text attribute values → canonical UUIDs during apply; write ids into

### 6.1 Schema (add to Group D block in `catalog_migrations.go`, after the master_cosmetics drop ~:951; all idempotent)
- `catalog.brands` (id UUID PK, canonical TEXT, slug TEXT, created_at) + `idx` UNIQUE on slug.
- `catalog.brand_aliases` (id, brand_id FK→brands ON DELETE CASCADE, raw_token TEXT, confidence,
  source, created_at, **UNIQUE(raw_token)** — brand aliases are global).
- `ALTER TABLE catalog.master_products ADD COLUMN IF NOT EXISTS brand_id UUID REFERENCES catalog.brands(id)`
  + index. (Additive — keep free-text `brand` for V5; brand is not a V5 search filter.)
- **8 dim pairs**, one repeated pattern (mirror unit_aliases) for keys
  `skin_type, concern, target_area, free_from, benefits, color, material, size`:
  - `catalog.dim_<key>` (id UUID PK, canonical TEXT, slug TEXT, created_at, UNIQUE(slug)).
  - `catalog.dim_<key>_aliases` (id, dim_id FK→dim ON DELETE CASCADE, tenant_id UUID NULL=global
    REFERENCES tenants ON DELETE CASCADE, raw_token TEXT, confidence, source, created_at,
    **UNIQUE(tenant_id, raw_token)**) + partial index on raw_token WHERE tenant_id IS NULL.
- **Mark controlled attrs data-driven:** `ALTER TABLE catalog.master_field_definitions ADD
  COLUMN IF NOT EXISTS dim_table TEXT` (NULL = free-text; non-null names the dim table).
  Chosen over a `bool` (normalizer needs the table name → stays data-driven) and over reusing
  `type='enum'` (controlled arrays have `type='array'`; `enum_values` store strings not UUIDs).
- **Ingredients:** tables already exist — no DDL.

### 6.2 Seed (after the cosmetics registry seed ~:910, idempotent ON CONFLICT DO NOTHING)
- Step A — `UPDATE master_field_definitions SET dim_table='dim_<key>'` for cosmetics
  `skin_type/concern/target_area/free_from/benefits`.
- Step B — `INSERT … master_field_definitions` registering `color/material/size` for
  **furniture + apparel + electronics** (this is what proves vertical-agnostic, DoD 6.7).
- Step C — seed a **small** canonical core per attr (~6–10 values) + aliases (join on slug).
  E.g. skin_type: oily/dry/combination/normal/sensitive/all with aliases (oily-prone, greasy,
  dehydrated, combo, "all skin types", …). Let the long tail flow to candidates — the candidate
  queue IS the controlled-growth mechanism (don't over-seed). **Brand gets NO canonical seed**
  (discovered from data).

### 6.3 Output-key convention into tier2
- controlled `type='array'` → `tier2.<key>_ids` (UUID array), e.g. `tier2.skin_type_ids` (DoD 6.4).
- controlled `text`/`enum` → `tier2.<key>_id` (single UUID), e.g. `tier2.color_id`.
- Raw human value stays under existing `tier2.<key>` (display fallback, no loss).
