# Chat session kill switch — v5 engine side (2026-06-08)

## Context
Owner wants the curator cockpit to terminate chat sessions (per-chat + a
two-gate "kill ALL" incident switch). v5 had **no** notion of a closed session
(only gate was "state row exists"), so a curator-only flag would be cosmetic —
the engine would keep serving the session. This adds the engine-side mechanism
curator calls. No apology message (owner's call). Transport is request/response,
so a killed user learns of it on their next turn (no server push).

## Approach
Soft-kill via a `killed_at` stamp + a single gate in `GetState` (every
continuation path — pipeline/actions/navigation — funnels through it), exposed
through internal-key-gated control endpoints that curator calls.

## Files changed (project_v5/backend)
- `internal/domain/errors.go` — new sentinel `ErrSessionKilled`.
- `internal/adapters/postgres/state_migrations.go` — idempotent `ALTER … ADD
  COLUMN IF NOT EXISTS killed_at TIMESTAMPTZ, killed_reason TEXT` on
  `v5_chat_sessions`.
- `internal/adapters/postgres/postgres_state.go` — `GetState` does a cheap PK
  pre-check; returns `ErrSessionKilled` when `killed_at` is set (the existing
  big state SELECT is untouched). Span error-exemption updated.
- `internal/handlers/handler_session.go` — `Kill` (POST
  `/api/v1/internal/session/{id}/kill`) + `KillAll` (POST
  `/api/v1/internal/sessions/kill-all`, active-in-30min, all tenants) +
  `checkInternalKey` (constant-time X-Internal-Key vs `V5_INTERNAL_KEY`; empty
  key ⇒ 503). Soft UPDATE, never DELETE.
- `internal/handlers/routes.go` — register the two internal routes.
- `internal/handlers/middleware_tenant.go` — exempt `/api/v1/internal/` from
  WithTenant (tenant-agnostic control plane).
- `internal/handlers/handler_pipeline.go` — map `ErrSessionKilled` → HTTP 409
  "session closed" (clean, not a 500; no error trace persisted).

## Env
`V5_INTERNAL_KEY` set on the v5-engine Railway service (production). Curator
holds the same key + `V5_INTERNAL_URL` and calls these endpoints.

## Verification
`go build ./...` + `go vet ./...` green. Post-deploy smoke: POST a bogus
session id to `/api/v1/internal/session/<uuid>/kill` with the key ⇒ 200
`{killed:false}` (proves route + tenant-exempt + key gate + migration ran);
without the key ⇒ 403.

## Known gaps
- Apology message intentionally omitted; killed turns surface as the widget's
  generic error bubble on the user's next message.
- 409 mapping added to the pipeline path only; actions/navigation on a killed
  session still return their generic error (still blocked, just less tidy).
- kill-all scopes to sessions active within 30 min across all tenants.
