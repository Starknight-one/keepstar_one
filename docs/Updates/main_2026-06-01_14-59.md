# Engine purity: sever the engine→anthropic leak + guard test

**Date:** 2026-06-01 14:59 · **Branch:** main

## Context
Entering the production-ready / engine-polish phase. The whole-project audit
(memory: project-architecture-audit) settled the question "split the pipeline
out of v5?" with **don't split** — `project_v5/internal/engine/` is a pure
render library and the only architectural argument for a split would be its
purity. But the audit found one leak that broke that purity: the
token-measurement scaffolding `internal/engine/tokens/count_tokens.go` imported
`internal/adapters/anthropic`, pulling the Anthropic adapter into the engine
tree even though nothing in the render path uses it. This is the "clean the
engine before prokachka" quick win.

## Approach
The leak was test/diagnostic scaffolding (`//go:build tokens` measurement,
never asserts — logs token counts for prompt design) living in the wrong place.
Rather than delete working scaffolding or inject an interface, **relocate the
package out of the engine tree** so the engine is pure by construction, then
**lock the invariant with a test** so it can't regress.

## Files changed
- **Moved** `project_v5/backend/internal/engine/tokens/` →
  `project_v5/backend/internal/measure/tokens/` (git rename, history preserved;
  the `sketches/` embed dir moved with it). The package's own imports of
  `adapters/anthropic` + `domain` are unchanged — they're legitimate from a
  diagnostic package, just not from inside `engine/`.
- **Added** `project_v5/backend/internal/engine/purity_test.go` —
  `TestEnginePurity` walks every non-test `.go` under `internal/engine/`,
  parses imports (`parser.ImportsOnly`, so build-tagged files are still
  checked), and fails if any import is a `keepstar_v5/internal/...` package
  other than `internal/domain` or `internal/engine/...`. Encodes: engine may
  depend only on stdlib, third-party, domain types, and its own subpackages.
- **Edited** `project_v5/backend/internal/prompts/agent2_prompt_test.go` —
  fixed a stale comment pointer (`engine/tokens` → `measure/tokens`).
- **Edited** `project_v5/backend/internal/usecases/agent1_execute_test.go` —
  added the missing `SearchProjection` method to the `fakeCatalog` test double.
  This was **pre-existing rot** (unrelated to the move): `SearchProjection` had
  been added to `ports.CatalogPort` and `catalog_search` now uses it, but the
  fake wasn't updated, so the entire `usecases` test package failed to compile
  (dark suite). The fake mirrors `VectorSearch` — returns the canned products.

## Verification
- `go build ./...` — OK.
- `go vet ./...` — clean (was failing on the dark `usecases` suite before the
  fake fix).
- `go test ./...` — all packages `ok` / `[no test files]`, no FAIL.
  `internal/engine` passes incl. the new `TestEnginePurity` guard.
- `go vet -tags=tokens ./internal/measure/tokens/...` — the build-tagged
  measurement scaffolding still compiles at its new home.
