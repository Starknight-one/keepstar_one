# Chunk 4 — first product card preset + replicate + image binding

**Branch**: v5
**Date (UTC)**: 2026-05-02 17:28

## Context

After chunks 1-3 V5 had the engine, sectional state, and the binding layer
— but no preset to render and no fan-out mechanism to turn one preset into
N cards. Until that bridge is built we can't measure tokens or quality
against V4. This chunk closes the gap with the first end-to-end pipeline
that does NOT involve an LLM: load a preset from DB, fan it out across
catalog products, bind, and verify each cloned card holds the right data.

A second outcome of the user-direction conversation that drove this chunk:
the existing KeepstarCanvas tables in `project_admin/` are flagged for
removal — the future canvas will be a **separate v9 microservice** embedded
into admin that reads/writes V5's preset tables as a client. So
`v5_presets` / `v5_preset_versions` are the **final shape**, not a
stopgap. That landed in `docs/v5-known-gaps.md` alongside the chunk.

Plan: `docs/Updates/v5/plans/chunk-4-first-preset.md`.

## Approach

Verbatim execution of the approved plan with one significant adjustment
mid-flight: domain.Preset stores the doc body as `json.RawMessage` rather
than a `*engine.Document`. Reason: `engine.binding_to_map.go` already
imports `domain` (for `domain.Product`), so adding a domain → engine
dependency would have created a cycle. Keeping the domain layer
engine-agnostic mirrors how chunk 2 stores `Current.Template` as
`map[string]interface{}` — engine-shaped data is unmarshalled at
consumption sites.

Two real bugs the plan-agent surfaced and the implementation fixed:
1. **ID collision after replicate × ComponentResolver**: the resolver
   forces `clone["id"] = NodeID(refNode)` (`component_resolver.go:98-100`),
   so cloning a RefNode N times via ExpandReplicates and then expanding
   each would collapse all N expanded clones onto one id. Fix:
   `ExpandReplicates.reIDSubtree` mints a fresh id on every node in the
   clone subtree.
2. **`dataIndex` not inherited by descendants**: the chunk-3 `dataIndexOf`
   only read the node's own attribute, so atoms inside a replicated card
   would all bind to `data[0]`. Fix: rewrote the `BindData` walker to
   thread an inherited `dataIndex` from the nearest ancestor; explicit
   child markers still override.

Replicate is implemented as a pre-bind step (`ExpandReplicates(doc, count)`)
rather than a Command on history. Reasoning lives in the replicate.go
preamble: replication is a render-time projection of preset+data, parallel
to `ComponentResolver.Expand`; nothing needs to undo it (LLM never sees
the expanded tree, the canvas edits the un-replicated source).

Image binding writes to `fills[0].image` with shape
`{type:"image", image:"<url>", mode:"fill"}`. The `image` payload key is
v9-convention-aligned but **not yet confirmed** against v9 TS source —
flagged as a known gap; centralised as `attrFillImageURL` so a single
rename suffices if the wire format uses `url` or `src`.

Image atoms with non-string bound values (defensive guard against
mis-shaped catalog rows) land in `BindResult.Missing` rather than
silently coercing junk into a fill URL.

Replicate semantics for nested markers: outer wins, inner is stripped
during clone (combinatorial blow-up avoided; nested replication isn't a
real preset shape today).

`postgres_state_integration_test.go::setupClient` now also runs
`RunPresetMigrations` so any integration test (state, catalog, preset,
end-to-end) gets the full v5 schema with one helper call.

## Known gaps / caveats

All carried into `docs/v5-known-gaps.md`:

- **Image-fill body shape unverified** (`{type:"image", image, mode}`) — V5
  internal consistency is fine; needs grep against v9 TS source before any
  frontend renderer port. Single rename via `attrFillImageURL` if wrong.
- **GroupID stamping deferred** — V4's `rg-{counter}` shared by replicate
  clones is needed only by cross-widget constraints, which chunk 4 defers
  entirely. Will land alongside the constraint engine.
- **Nested replicate is a stripped no-op** — outer marker fans out, inner
  markers inside the clones are deleted. Not a real preset shape today;
  re-evaluate when one shows up.
- **Admin KeepstarCanvas tables flagged for removal** — current
  `admin.tenant_presets` / `_versions` / `_components` / `_design_tokens`
  schemas in `project_admin/` are slated for tear-down (not migration);
  v9-canvas microservice will read/write V5's preset tables as a client.
- **PresetPort is read-only** — Save/Publish/Fork/Archive land with the
  v9-canvas microservice (Stream B).
- **Agent2 prompt-builder with `<fields>` block** still pending for chunk 5.
- **`Current.Template` typed accessor** still pending — DocumentJSON pattern
  (chunk 4) suggests we'll just unmarshal at consumption sites; revisit
  during pipeline integration in chunk 6.

What to watch in next chunks:
- Chunk 5 will exercise the `<fields>` prompt block consumer; if heroImage
  / dataIndex inheritance has a corner case, it surfaces there first.
- The image-fill shape known-gap should be closed before any frontend
  renderer port — V5 is internally consistent but unverified against v9
  wire format.
