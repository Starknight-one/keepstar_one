## Approach

### Scaffold

`project_v5/frontend/` mirrors V4's structure: Vite + React 19 + IIFE
bundle + Shadow DOM mount + the same `shadowDomCss` plugin trick that
suppresses regular `.css` imports so the bundle ships exactly what
`widget.jsx` imports via `?inline`.

- `vite.config.js` is a function form `({ mode }) => ...` so
  `NODE_ENV=production` is baked only for actual builds. Under Vitest
  `mode==='test'` and React keeps its development build (necessary for
  `@testing-library/react` to find `React.act`).
- `package.json` adds Vitest + jsdom + @testing-library/{react,jest-dom}
  on top of V4's React/Vite deps.
- `index.html` is the dev host page (`window.__KEEPSTAR_V5_WIDGET__`
  config); `public/widget.html` is the production-style embed test page
  loaded after `npm run build`.

### Mount

`src/widget.jsx` (IIFE entry):
- Detects the embed `<script>` via `document.currentScript` with a
  fallback selector. Reads `data-tenant` + `data-api`; falls through
  to `window.__KEEPSTAR_V5_WIDGET__` for dev.
- Creates `<div id="keepstar-v5-widget">` host, attaches Shadow DOM
  (mode: open), injects Google Fonts + concatenated `?inline` CSS into
  one `<style>`, mounts React.

### Layout shell

`src/widget.css` defines the brand vars + the V4-equivalent layout:
- `.kw-overlay` — fixed, inset:0, flex row.
- `.kw-display` — flex:1, max-width 1200, centred — widgets render here.
- `.kw-chat` — width:360px right column — ChatPanel here.
- Brand: `--kw-blue: #5BA4D9`, `--kw-orange: #F0924A`. No purple.
- Wrapper styles for `kw-badge / kw-tag / kw-pill / kw-button /
  kw-link / kw-alert`.

### Renderer

`src/renderer/`:
- `SceneGraphRenderer.jsx` — top-level walker. Skips reusable
  component definitions (`reusable: true`); maps remaining root
  children through `NodeRenderer`. Logs `[v5-renderer] document` debug
  per render with node count / top-level types.
- `NodeRenderer.jsx` — type dispatcher. Dispatches `frame` / `group` /
  `text` / `image` / `ref`. Unknown types → `console.warn` +
  no render.
- `nodes/Frame.jsx` — flexbox via `data-direction` / `data-gap` /
  `data-align` / `data-justify` attributes hooked up to CSS.
- `nodes/Group.jsx` — vertical column wrapper.
- `nodes/Text.jsx` — pipes `node.content` through `format.js` then
  `wrapper.js` then renders as `<p class="kw-text">` with
  `data-fontsize` / `data-fontweight` attrs and inline color/lineClamp.
- `nodes/Image.jsx` — reads `node.fills[0].url` (V5 image-fill shape
  after chunk-5.5 alignment) with fallback to `node.content` (string
  URL or array of URLs). Sets `data-aspect` for CSS aspect-ratio.
- `nodes/Ref.jsx` — backend resolves refs before they reach the
  frontend; this is a safety pass-through that renders any inlined
  children (or nothing if resolution failed).

### Format + wrapper

`src/renderer/format.js`:
- Eight format kinds: `currency` / `stars` / `stars-compact` /
  `stars-text` / `percent` / `number` / `date` / `text`.
- `currency` accepts already-formatted strings (passes through if it
  starts with $/€/£/¥/₽), pure numbers (Intl.NumberFormat USD), or
  numeric strings.
- `stars` produces unicode stars + ½ + ☆; compact / text variants
  drop the empty stars or the unicode entirely.

`src/renderer/wrapper.js`:
- `none` / `badge` / `tag` / `pill` / `alert` / `link` → wrapped in
  styled `<span>` (or `<a>` for link).
- `button` → real `<button class="kw-button">` with onClick that
  `console.log('[v5-action]', ...)` carrying the wrapper / nodeId /
  fieldBinding / content + a `'TODO: not wired'` hint. P0-C will
  replace the handler with an actions endpoint POST.

### Chat shell

`src/chat/ChatPanel.jsx` + `MessageList.jsx`:
- 360px right column. Input at the bottom, message history above.
- Three message kinds: user (right-aligned blue), bot (left-aligned
  grey), error (full-width red monospace).
- Bot ack message summarises what just rendered: `rendered preset
  "X"` / `applied N ops on the current view` / `rendered preset "X"
  with N ops`.

### API client + WidgetApp

`src/api/client.js`:
- `initSession({ baseUrl, tenantSlug })` → POST `/session/init` with
  `X-Tenant-Slug` header.
- `pipelineRequest({ baseUrl, tenantSlug, sessionId, query })` → POST
  `/pipeline` with JSON body.

`src/WidgetApp.jsx`:
- On mount: calls `initSession`, stores `sessionId`.
- `handleSend(query)` appends user message, calls `pipelineRequest`,
  stores returned `document` for the renderer, appends bot ack.
- Logs `[v5-renderer] spans` per turn with summarised `agent2.llm`
  attrs (input tokens, cost) so devtools surfaces cost without a
  debug page.

## Known gaps / caveats (after this chunk)

- **Action click handlers are no-ops.** Buttons render as real
  `<button>` elements but onClick only console.logs. P0-C item 7-8.
- **No drill-down / prefetch.** Clicking a card does nothing. P0-C
  item 9.
- **No back navigation.** P0-C items 10-11.
- **No session restore from localStorage.** F5 clears the session.
  P0-C scope.
- **No Yoga-WASM layout.** Flexbox-CSS only — sufficient for today's
  preset shapes (column / row / grid via wrapping). Add Yoga when a
  preset needs auto-sizing measurements.
- **Limited node types.** `rectangle` / `ellipse` / `line` / `polygon`
  / `path` / `note` / `prompt` / `context` / `icon_font` not
  implemented. Today's presets only use frame / group / text / image
  / ref. Add as needed.
- **No constraints rendering.** V5 backend doesn't emit constraints
  yet (P2 item 20). When it does, the renderer may need extra
  attributes.
- **No widget/status check.** V4 has a `/widget/status` endpoint that
  the embed pre-checks before mounting (kill-switch per tenant). V5
  doesn't expose it yet; the widget mounts unconditionally.
- **Bundle is built for dev too** when `npm run dev` is used; that's
  fine for local but means no minification at the dev path.
