## Context

Chunk 6a shipped the SDK adapter; this chunk lands the rest of the LLM-in-the-loop work for V5: tool registry, visual_assembly tool, Agent2 prompt-builder, prompt cache, Agent2Execute use case, and a live end-to-end smoke test that runs against real Anthropic Haiku + real Neon catalog data.

The session also closed the chunk-5.5 HARD GATE: the V5 cacheable prefix must clear ≥ 4500 tokens for prompt caching to fire reliably. Chunk 5.5 measurement had V5 at 3001, with a +70.5% effective cost vs V4 over 10 turns. After this chunk's prompt body and tool-def grew, the V5 prefix lands at **4540 tokens** with a **22.7% effective cost reduction vs V4**.

## Approach

**Tool registry + ToolContext**: minimal Go interfaces. `domain.ToolContext` carries SessionID + TenantSlug + TurnID per call; ports are held by the tool via constructor. `tools.Registry` is concurrent-safe map with byte-stable sorted-by-name iteration so prompt-cache hashes don't drift between runs.

**visual_assembly V5 tool**: schema declares `preset` + `replicate` + `ops`. Implementation handles preset+replicate end-to-end through the V5 engine pipeline (`Materialise → ExpandReplicates → ResolveAndInline → BindData`) and writes the resulting Document to `state.Current.Template` via `StatePort.UpdateTemplate`. The `ops` field is parsed and logged but applied as a no-op for now — chunk 6c will wire `engine.CommandHistory` translation. Keeping the schema declaration in 6b means 6c is purely additive; the prompt and LLM contract don't drift.

**Schema stability**: `TestVisualAssemblyDefinitionStable` asserts `json.Marshal(def.InputSchema)` produces byte-identical output across calls. Schema drift was a real V4 problem (any map iteration order randomness busts the cache); the unit test guards against regression.

**Prompt body — closing the cache gate**: ported V4's BUILDING / FIELD BINDING / DECISION RULES / ANTI-PATTERNS sections, adapted for V5's preset+replicate-only API surface. Added V5-specific sections (REPLICATE, TREE_MAP shape, FORMAT + WRAPPER pass-through) absent from V4. Final body: 12,920 chars / ~3K tokens. Combined with the 2KB tool def, V5's cacheable prefix is **4540 tokens** — comfortably above the 4500 stable-cache threshold.

**Per-tenant prompt cache**: `usecases.PromptCache` wraps `sync.Map`. Key: tenant slug (or UUID — adapter handles both). Value: assembled prompt + builtAt timestamp. Build calls `prompts.FormatFieldsBlock` → `<fields entity="product">` listing the tenant catalog vocabulary, sorted by FieldDefinition.Priority for stable bytes. No invalidation in 6b; chunk 6c+ will hook into a tenant_design_context version snapshot identical to V4.

**Agent2Execute use case**: single-turn tool loop ported from V4 (`agent2_execute.go:103-383`), simplified — no Agent1 (V5 doesn't have it yet), no design-context (deferred). History trimmed to last 4 messages (V4-proven `historyLimit = 4`). `CacheConfig{CacheTools: true, CacheSystem: true, CacheConversation: len > 1, ToolChoice: "any"}`. Graceful retry: on tool transport-error, retry once with empty input (V4 fallback). Tool-side IsError responses are NOT retried — they're informational for the LLM next turn.

**Live smoke test on Neon + Haiku**: gated on both `ANTHROPIC_API_KEY` and `TEST_DATABASE_URL` (build tag `integration && live`). Picks heybabes-style tenant with ≥ 3 products, seeds product_card preset (with EXACT name `"product_card"` so the LLM's catalog choice from the prompt matches the DB) plus price_rating + brand_badge components. Pre-populates `state.Current.Data` with 3 catalog products (simulates "Agent1 already ran"). Runs Agent2Execute twice — turn 1 to verify cache write, turn 2 to verify cache read. Both pass.

## Known gaps / caveats

- **Ops applier deferred to 6c** — schema declares ops, prompt teaches them, but the tool currently logs+ignores. Single conditional in `tool_visual_assembly.go` is the FIXME anchor for 6c.
- **No Agent1** — `state.Current.Data` is populated upstream (smoke test does it manually). When V5 grows Agent1 (catalog_search / state_filter), Agent2 won't need to change.
- **`<tenant_design_context>` block deferred** — V5 prompt has a hardcoded preset catalog. When chunk 6c adds the tenant design-context loader, the prompt cache will need invalidation hooks (V4 pattern via version snapshot).
- **Smoke test seeds preset with exact name** — the helper `seedPresetWithExactName` deletes any prior row with the same name first. Live with that pattern; multi-tenant production shouldn't hit it because real preset names are tenant-scoped.
- **Cache thresholds in pricing math live in tokens/measurement_test.go** — the live smoke test logs raw token counts; the gate is checked by the measurement test, run separately.
