## Approach

Скопирован V4 deploy pattern без архитектурных изменений:

1. **`/readyz` handler** (`handler_readyz.go`). Closure над `pgxpool.Pool`
   с `pool.Ping(ctx)` и 1-секундным timeout. 200 ok / 503 not_ready.
2. **Static fileserver** в `routes.go`. Catch-all `GET /` mirror'ит
   V4 `cmd/server/main.go:347-357`: пытается отдать файл из `staticDir`,
   fallback на `index.html`, иначе 404. Параметр `staticDir` приходит
   из `config.StaticDir` (env `STATIC_DIR`, default `./static`). Когда
   директории нет (локальный `go run` без vite-билда) — fileserver не
   регистрируется.
3. **`config.go`** — новое поле `StaticDir`.
4. **`project_v5/Dockerfile`** — 3 stage'а mirror V4: `node:22-alpine`
   → vite build → `widget.js`; `golang:1.24-alpine` → `go build`;
   `alpine:3.21` runtime с `COPY --from=frontend /build/dist ./static`.
5. **Railway**:
   - Service `v5-engine` в `selfless-tranquility / production`.
   - Env vars: DATABASE_URL (тот же Neon что V4 / Admin / Curator),
     ANTHROPIC_API_KEY, OPENAI_API_KEY, TENANT_SLUG, LLM_MODEL,
     LOG_LEVEL, `RAILWAY_DOCKERFILE_PATH=project_v5/Dockerfile`.
   - `railway up --service v5-engine --ci` — первый deploy через CLI
     (без GitHub repo link — Vlad подключит репо в dashboard, после
     чего push в `v5` будет автодеплоиться).
   - `railway domain` → `v5-engine-production.up.railway.app`.

## Known gaps / caveats

- **GitHub auto-deploy не настроен.** CLI flow для repo-link требовал
  интерактивного GitHub OAuth и отдан Vlad'у через Railway dashboard
  (Settings → Source → Connect GitHub repo, branch `v5`). После
  настройки каждый push в `v5` будет триггерить deploy. До этого момента
  обновлять prod нужно через `railway up --service v5-engine --ci`.
- **Нет staging environment.** Deploy сразу в production. Когда появится
  реальный пользовательский трафик — добавим staging env.
- **`/readyz` пингует только Postgres**, не Anthropic. Anthropic
  outages surface как 5xx на `/api/v1/pipeline`. Достаточно для первой
  фазы.
- **Нет CDN перед widget.js.** Railway отдаёт static напрямую. Acceptable
  на текущем этапе — при росте трафика поставим CDN.
- **Frontend (V5 widget) деплоится в том же Docker.** Если в будущем
  захочется отдавать виджет с отдельного домена (`chat.keepstar.one`) —
  отдельный чанк.
- **Item 17 (latency baseline) не отдельным шагом.** Первая turna 7.2s
  включает cold-cache LLM call + cold connection pools — это first-turn
  cost, не steady-state. Для полноценного latency baseline'а нужен 20-30
  prompt smoke на разных prompts (chunk 15 / item 16).
