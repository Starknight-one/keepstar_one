## Context

Chunk 6d shipped a working SpanCollector — every request gets a fresh collector via the logging middleware, hot adapters and use cases call `sc.Start(name)` to record timed spans, the pipeline handler returns the sorted span list in the response. Useful for "is anything firing", but the model was too thin for real diagnostics:

- **No parent/child** — flat list, hierarchy was reconstructed by sorting `StartMs ASC, DurationMs DESC`, a heuristic that breaks under parallel goroutines or equal-millisecond starts.
- **Only one freeform `Detail` string** — no way to attach `tokens.input=4110`, `cost_usd=0.012`, `rows=3`, `tenant_id=X`. Per-LLM-call usage was squashed into `pipelineResponse.usage` as a sum across both agents.
- **No status / error** — couldn't tell from the JSON whether a span succeeded.
- **No request correlation at the span level**.

User flagged: "трейс был так себе и чего-то явно не хватало". This chunk extends the model and migrates the hot call sites. No `/debug/traces` UI page yet — that's still chunk 12, the actual rendering.

After this chunk: `pipelineResponse.spans[]` looks like a real trace — every span has `id` + `parent_id`, LLM spans carry `tokens.input` / `cache_read` / `cost_usd`, Postgres spans carry `rows` / `tenant_id`, errored spans carry `status="error"` + `error="…"`. Live HTTP test asserts all of this.

## Approach

### Extended `Span` shape

```go
type Span struct {
    ID         string         `json:"id"`              // monotonic "s-N"
    ParentID   string         `json:"parent_id,omitempty"`
    Name       string         `json:"name"`
    StartMs    int64          `json:"start_ms"`
    EndMs      int64          `json:"end_ms"`
    DurationMs int64          `json:"duration_ms"`
    Status     SpanStatus     `json:"status,omitempty"` // "ok" | "error"
    Error      string         `json:"error,omitempty"`
    Attrs      map[string]any `json:"attrs,omitempty"`
    Detail     string         `json:"detail,omitempty"` // legacy
}
```

### New ctx-aware API

```go
ctx, span := sc.StartSpan(ctx, "agent1.llm")
defer span.End()
span.SetAttrs(map[string]any{"model": ..., "tokens.input": ...})
if err != nil { span.SetError(err) }
```

Parent tracking: `StartSpan` reads the active span ID from a separate ctx key, stamps it as `ParentID` on the new span, then writes the new span's ID into the returned ctx. Nested `StartSpan` calls auto-link.

Legacy `Start(name)` API kept untouched — every existing call site still works byte-for-byte. Migration is opt-in: hot paths now, secondary paths later.

### LLM-span attrs (most valuable)

After every `llm.ChatWithToolsCached` call, before the span ends:

| key                   | source                              |
|-----------------------|-------------------------------------|
| `model`               | resp.Usage.Model                    |
| `tokens.input`        | resp.Usage.InputTokens              |
| `tokens.output`       | resp.Usage.OutputTokens             |
| `tokens.cache_read`   | resp.Usage.CacheReadInputTokens     |
| `tokens.cache_creation` | resp.Usage.CacheCreationInputTokens |
| `cost_usd`            | resp.Usage.CostUSD                  |
| `tool_calls`          | len(resp.ToolCalls)                 |
| `stop_reason`         | resp.StopReason                     |

Now the trace JSON shows "agent1.llm: 1819 input, $0.001" vs "agent2.llm: 4540 input, 6244 cache_read, $0.005" separately — today both numbers were summed into one `pipelineResponse.usage` struct.

### Postgres-span attrs

| span                          | attrs                                            |
|-------------------------------|--------------------------------------------------|
| `postgres.GetState`           | `session_id`, `step` (after read)                |
| `postgres.UpdateData`         | `session_id`, `product_count`, `step` (assigned) |
| `postgres.UpdateTemplate`     | `session_id`, `step` (assigned)                  |
| `postgres.ListProducts`       | `tenant_id`, `limit`, `has_search`, `has_filter`, `rows`, `total` |
| `postgres.BuildCatalogDigest` | `tenant_id`, `total_products`, `category_groups`, `shared_filters`, `top_brands`, `top_ingredients` |

Errors flagged via `Status="error"` (e.g. unique-constraint violations, marshal failures) — `domain.ErrSessionNotFound` deliberately NOT flagged because it's a domain signal, not a transport failure.

### Pipeline-span attrs

`pipeline.execute` (root) carries `request_id` (from `domain.RequestIDFromContext`), `tenant_slug`, `agent1_ms`, `agent2_ms`, `microcontext`. The request_id mechanism uses a new `domain.WithRequestID` / `domain.RequestIDFromContext` pair; logging middleware stamps it, use cases read it. Cleaner than threading the id through every request struct.

### Tool-span attrs

`agent*.tool.<name>`: `tool_name`, plus `is_error=true` when `result.IsError`. Deterministic-guard span on Agent1 carries `bypassed=true`.

### Backward-compat retained

- Legacy `sc.Start(name)` API untouched.
- Secondary postgres methods (`GetTenantBySlug`, `GetProduct`, preset / component reads) keep the legacy API. Migrate piecemeal in future if their traces become useful.
- Old `usecases.startSpan` helper retained alongside new `withSpan` — used by un-migrated call sites. Will retire when the last call site flips.
