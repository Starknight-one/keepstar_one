# Chunk 2 — port V4 state + delta-stream into V5

**Branch**: v5

## Context

Chunk 1 (commit `5a0a89e`) ported v9's TypeScript scene-graph engine to Go in
`project_v5/backend/internal/engine/`. With the engine in place, the next gap
is **session state + delta-stream** — without these the engine has nothing
to render against and no audit trail. Vlad called the delta-stream out
explicitly: foundational for rollback, reconstruction, multi-actor
coordination, and trace.

This chunk closes that gap by porting V4's sectional state model verbatim
into V5, with one substantive change: the `Template` zone now stores a
scene-graph `engine.Document` JSON instead of a Formation. The V4 surface
(14-method `StatePort`, sectional zones, append-only deltas, view stack,
conversation/agent2 history) is preserved 1:1 so we can compare V5
behaviour against V4 in subsequent chunks.

Plan: `docs/Updates/v5/plans/chunk-2-state-delta.md` (frozen copy of the
plan-mode artifact at `~/.claude/plans/spicy-dreaming-waffle.md`).

## Approach

Verbatim port of V4 sources with three deliberate adaptations:

1. **Tables prefixed `v5_*`** so V5 sessions live next to V4 prod data
   without collision (user decision Q1). Single fresh migration replaces
   V4's 8 incremental ALTERs.
2. **Same DATABASE_URL** as V4 (user decision Q2). One Neon Postgres,
   v5 just creates new tables.
3. **`engine.Document` JSON** stored in `current_template` instead of
   Formation. Round-trip already verified by chunk 1's
   `TestDocumentJSONRoundTrip`. Storage type unchanged
   (`map[string]interface{}` over JSONB) — only the content shape changed.

V4 bugs ported as-is on purpose:
- `zoneWriteWithDelta` is two separate `pool.Exec` calls, not a tx —
  zone update can succeed while AddDelta fails. State is source of
  truth; deltas are an audit log; caller can retry.
- `AddDelta` MAX(step) CTE has TOCTOU race; UNIQUE(session_id, step)
  protects integrity. Per-session concurrent writers are not a real
  scenario in chat; not fixing in this chunk.
- `applyDelta` Push/Pop/Rollback/Remove cases are stubs; replay only
  honours add/update/template. Improving applyDelta is chunk-7 work.

`domain.SpanFromContext` blocks dropped — chunk 1 didn't port the tracer.
Re-add when chunk 6 wires the tracer port.

## Known gaps / caveats

- **Not ported**: span tracing (chunk 6), product/service repository
  adapters (chunk 3+), HTTP handlers, Agent1/Agent2 wiring.
- **applyDelta semantics** are V4-simplified; full delta replay (with
  proper Push/Pop ViewStack mutation, Remove handling, Rollback nesting)
  is a chunk-7 task.
- **No transaction around zone-write + delta-write**. Carried over from
  V4 as noted; revisit alongside LLM adapter wiring.
- **AddDelta race**: under concurrent zone-writes per session, MAX(step)
  CTE can collide. UNIQUE constraint preserves integrity, retry is
  caller-side. Not a real chat scenario today.
- **Migration not auto-run**: `RunStateMigrations` exists but is not
  invoked anywhere yet — chunk 6 will wire DI.
- **Mock StatePort returns shallow copy** of state in `GetState` to match
  Postgres "rehydrate from JSONB" semantics. If tests later need mutation
  visibility across calls they should use the live Postgres adapter
  behind `//go:build integration`.
