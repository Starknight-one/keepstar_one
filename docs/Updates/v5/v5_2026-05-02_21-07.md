## Context

Chunks 1-6d shipped V5 end-to-end as far as Agent2 (rendering): scene-graph engine, presets/components, LLM adapter, ops applier, HTTP server with tx-safe state writes and span tracing. But the HTTP `/api/v1/pipeline` only ran Agent2 — clients had to pre-populate `state.Current.Data` themselves before each call, which is not a real product.

Agent1 is the data-retrieval half of the pipeline: it takes the user query, decides whether to fetch new catalog data (`catalog_search`), filter what's already loaded (`_internal_state_filter`), or do nothing (style request), and writes results to `state.Current.Data` + `state.Current.Meta`. Agent2 then renders. This chunk ports V4's Agent1 to V5 and wires the two-agent pipeline behind `/api/v1/pipeline`.

After this chunk: a single `curl POST /api/v1/pipeline` with a real user query (e.g. "Покажи 3 продукта") triggers Agent1 → Agent2 sequentially. Agent1 picks `catalog_search` against the live catalog; Agent2 picks `visual_assembly` against the published preset. Live test green at $0.0126/turn-1, $0.0054/turn-2 (cache hit on combined prefix).

## Approach

### Three Agent1 tools (commit bae9fde)

All three register in the existing `tools.Registry` (sorted by name → byte-stable cache hashes). Agent1 filters by name prefix at call time (`catalog_*` / `_internal_*`).

- **`catalog_search`** — keyword-only port of V4. Schema mirrors V4 minus `service` entity_type (V5 catalog has products only). V5's `vector_query` parameter routes into `ListProducts.Search` (multi-word AND-logic ILIKE in `postgres_catalog.go:139-159`). No vector search, no RRF — V4's hybrid path deferred until V5 grows an EmbeddingPort. Empty result preserves existing screen (records empty delta only). Rubles ↔ kopecks (×100) at the LLM boundary. Brand-strip trick from V4: if `filters.brand` is set, strip it from `vector_query` so the keyword query doesn't double-filter.
- **`_internal_state_filter`** — pure in-memory filter on `state.Current.Data.Products`. Brand / category / price-range / min-rating / text-match. 0-result preserves data + records empty delta (V4 tool_state_filter.go:111-128).
- **`_internal_history_lookup`** — reads deltas via `StatePort.GetDeltas`, optional `last_n` slice, case-insensitive match on `Action.Tool` + `Path`. Read-only.

### Agent1 prompt + catalog digest + use case (commit 5871ffe)

- `domain/catalog_digest.go` — verbatim port of V4 (`CatalogDigest` + `ToPromptText`).
- `CatalogPort.BuildCatalogDigest` — port of V4's `GenerateCatalogDigest` (4 SQL queries: category tree / shared filters / top-30 brands / top-30 ingredients via unnest). Drops V4's `GetCatalogDigest`/`SaveCatalogDigest` split — V5 builds on demand. Top ingredients uses `mp.key_ingredients` array directly so we don't depend on `catalog.product_ingredients` seeding.
- `prompts/agent1_prompt.go` — verbatim port of V4 system prompt + `BuildAgent1ContextPrompt` (`<state>` envelope). Drops V4's `current_display` field — V5 stores a scene-graph Document map at `state.Current.Template`, not a typed `RenderConfig`.
- `Agent1PromptCache` — separate from existing `PromptCache` (Agent2's `<fields>` block). Same shape: `sync.Map[tenantSlug] → built prompt`. Fail-open on tenant/digest fetch errors (returns base prompt unchanged — V4 pattern).
- `Agent1Execute` — single-turn tool loop with V4's deterministic guard (`filterTriggers && !styleFieldNames`). Bypasses LLM and runs `_internal_state_filter` directly when data is loaded AND query is an obvious subset request. CacheConfig: `CacheSystem=true`, `CacheConversation=len(messages)>1`, `CacheTools=false` (Agent1 tool defs sum below Haiku's 2048-token per-block minimum), `ToolChoice="auto"` (Agent1 may legitimately decline on style requests).

### Pipeline orchestrator + microcontext + handler rewire (this commit)

- `usecases/pipeline_execute.go` — runs Agent1 → microcontext signal → Agent2. Aggregates ToolCalls and Usage across both. Microcontext shapes:
  - `"new_search: N items found"` after `catalog_search`
  - `"filtered: N items"` after `_internal_state_filter`
  - `"history: deltas inspected"` after `_internal_history_lookup`
  - `"no_data_change"` otherwise (style request, bypass)
- `Agent2Execute` extended with optional `Microcontext` field; when non-empty, prepended as `<microcontext>...</microcontext>\n` to the user message. Same string is persisted to `Agent2History` so cache stays byte-stable on the next turn.
- `handler_pipeline.go` — dep `*Agent2Execute` → `*PipelineExecute`. Response gains `Agent1Ms` / `Agent2Ms` per-stage breakdown.
- `cmd/server/main.go` — registers all 3 Agent1 tools, builds `Agent1PromptCache`, wires `PipelineExecute`.
- `handler_pipeline_live_test.go` — extended to set up the full pipeline and assert `pipeline.execute` / `agent1.execute` / `agent1.llm` / `agent2.execute` / `agent2.llm` / `postgres.GetState` spans all fire.
- `engine/tokens/measurement_test.go` — added `TestAgent1PrefixSize` measuring Agent1's bare prefix (system + 3 tool defs, no digest). Logs gap to 4500-token stable-cache bar.

## Known gaps / caveats (after this chunk)

- **EmbeddingPort + pgvector + RRF** still deferred — V5 `catalog_search` is keyword-only. The `vector_query` parameter stays in the schema (LLM behavior unchanged) but the executor does keyword fallback.
- **Services entity** dropped from `catalog_search` schema. V5 catalog has products only; re-add when services land.
- **Catalog digest persistence** — V4 stores in `tenants.catalog_digest`; V5 builds on demand + in-process cache. Add `/api/v1/admin/invalidate-cache` endpoint when staleness becomes a real issue.
- **Agent1 prefix < 4500** — bare prefix measured 1819 tokens. Live test confirms turn-1 cache miss (cache_creation 6244 → cache_read 6244 on turn 2 once conversation history grows). V4 has the same gap; not blocking, just logged.
- **`<tenant_design_context>` block for Agent2** still deferred (chunk 6 carryover); blocked on canvas-microservice handshake.
