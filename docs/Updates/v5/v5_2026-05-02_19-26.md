## Context

Chunk 5.5 left V5 with all the engine + state + binding pieces in place but no LLM integration. Chunk 6 was identified as the "LLM in the loop" chunk and split into 6a/6b/6c/6d.

This session lands **6a** — the foundational LLM adapter. V4 made the deliberate choice to use **raw HTTP** for its Anthropic adapter, and that choice produced a long tail of pain (every new feature — count_tokens, cache_control variants, prompt-cache metrics, streaming, future thinking blocks — had to be hand-rolled and was error-prone). After explicit user direction "vote for SDK", V5 takes the opposite tack: official Go SDK as a dependency, hand-rolled HTTP only for things the SDK doesn't expose.

Outcome: V5 now has a working `LLMPort` implementation, validated against the live Anthropic API, and the chunk-5.5 token-measurement scaffolding has been migrated off its raw-HTTP stand-in and onto the SDK without changing the measurement numbers.

## Approach

**SDK choice**: `github.com/anthropics/anthropic-sdk-go v1.38.0`. Pulled via `go get`, brought in 9 transitive deps (jsonparser, jsonschema, tidwall toolkit, etc.) — all fine for a backend service.

**LLMPort surface — minimal**: only two methods, `ChatWithToolsCached` and `CountInputTokens`. V4 has four (`Chat`, `ChatWithTools`, `ChatWithToolsCached`, `ChatWithUsage`); production Agent2 only uses the cached variant, and tests don't need the others either. Skipping them outright means less code to keep in sync with the SDK.

**Cache-control placement — port the V4-proven pattern via SDK types**: tools last (in the sorted-by-name array), system first, history second-to-last (when there are ≥ 2 messages). Implementation reads `CacheConfig` flags and writes `CacheControlEphemeralParam{Type: "ephemeral"}` onto the right param-struct fields. **One subtle gotcha caught by unit tests**: the SDK's `param.IsOmitted` is a reflect-based `IsZero()` check, so an empty `CacheControlEphemeralParam{}` literal serialises away. Setting `Type: "ephemeral"` explicitly is required even though the SDK has a default tag — defaults only apply at marshal time after the field is decided non-omitted.

**`buildMessageNewParams` factored out for testability**: the function that assembles `anthropic.MessageNewParams` is a pure mapper; `chat_smoke_test.go` (live) covers end-to-end behavior, but `cache_placement_test.go` (unit) validates placement by inspecting the struct directly without making a network call. 8 cases pass: tools-only, system-only, history-only, all-three, no-op-on-single-message, tool_choice variants (auto / any / tool:NAME / unset), tool_use+tool_result conversion, plus pricing math (input+output and cache write+read).

**Cost calculation**: pricing table for Haiku 4.5 / Sonnet 4.5/4.6 / Opus 4.5/4.6/4.7 with the documented cache-write 1.25× / cache-read 0.10× factors. Unknown model id falls back to Haiku rates (with a flag in `usage.Model` so the caller can notice).

**Token-measurement migration**: `internal/engine/tokens/count_tokens.go` was a raw-HTTP stand-in shipped in chunk 5.5. Replaced with a thin shim that constructs the SDK adapter and delegates. The exported function signature is unchanged so `measurement_test.go` doesn't need any test-code changes — and re-running the test produces **identical numbers** to the chunk-5.5 baseline (V4 7235 / V5 3705 input tokens, V5 prefix 3001 < 4500 stable threshold, +70.5% effective cost over a 10-turn conversation). This is the right outcome: SDK adapter and raw HTTP should report the same input_tokens for the same input shape.

**Live smoke test**: hits Haiku 4.5 once with a 1-line prompt. Reports response text "OK", 28 input + 4 output tokens, $0.000048 USD. Build tag `live` keeps it out of regular `go test ./...`.

## Known gaps / caveats

- **CountTokens does NOT count cache_control hints** — the endpoint reports raw input regardless of caching. Means we can't predict cache hit/miss from `CountInputTokens` alone; we still need a real call to see `Usage.CacheReadInputTokens` / `CacheCreationInputTokens`. Fine for prefix-size gating (the chunk-6b hard gate is "prefix ≥ 4500 tokens"), not enough for runtime cache verification.
- **No retry / backoff** — SDK has built-in retry on 429/5xx but I haven't tuned it for our latency budget. Revisit in chunk 6d alongside the tracer port + `domain.SpanFromContext` re-add.
- **MaxTokens hardcoded at 4096** — fine for Agent2's tool_use response (~200-500 tokens typical), but should become configurable when the prompt-builder lands.
- **`ChatWithToolsCached` is the only exported chat method** — V4 has four. If anything later needs the un-cached / no-tools variants, port them then.
- **Cost table for Sonnet 4.6 / Opus 4.7 is approximate** — refresh against Anthropic's published prices before any billing-sensitive use.
- **Live smoke test is opt-in (build tag `live`)** — never runs in CI. Token-measurement test is also opt-in (build tag `tokens`).
