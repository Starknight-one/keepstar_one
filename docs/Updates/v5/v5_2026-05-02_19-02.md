## Context

Chunks 1-5 shipped a working V5 architecture (engine port → state/delta → binding → first preset → micropresets) green on live Neon integration tests. Before chunk 6 (LLM in the loop) lands, an audit surfaced four real problems and one missing measurement:

1. Latent `reusable:true` not stripped on nested ref expansion — would silently skip whole subtrees in BindData the moment a component references another component.
2. Image-fill body key `image` was a guess against v9; v9 source uses `url`.
3. `format` / `wrapper` properties — V4 has them as backend-stored pass-through props, V5 had nothing. Without them, a TextNode bound to a numeric field like `rating` carries a raw `4.5` in `content` and the frontend can't render it as `★ 4.5`.
4. Doc drift: known-gaps storage row lost track of `v5_components`; chunk 6 in the roadmap was overloaded.
5. Token-cost vs V4 declared as a hard constraint in the original plan but never measured.

This chunk closes the four problems and produces the first cache-aware token measurement, leaving chunk 6 with a smaller, more focused scope.

## Approach

**Step 1 — nested-ref `reusable` strip**: moved `delete(node, "reusable")` from `ResolveAndInline` into `ComponentResolver.expandRef` itself. Top-level + nested ref expansions are now both correct because the recursive call at lines 113-117 produces clones that are already definition-marker-free. Regression test `TestResolveAndInlineStripsReusableFromNestedRefs` builds a wrapper-component → leaf-component chain and asserts (a) no `reusable:true` survives in the resolved consumer subtree, (b) BindData fills the deepest leaf.

**Step 2 — image-fill key**: confirmed in v9 source (`packages/domain/src/value-objects/fill.ts:35-42`) — the canonical key is `url`, not `image`. Renamed `attrFillImageURL = "image"` → `"url"`. Updated tests and the integration assertion at `engine_pipeline_integration_test.go:276` (the integration assertion for hero-image url on cloned cards).

**Step 3 — format / wrapper as pass-through properties**: V4-aligned architecture confirmed — leaf nodes carry `format` and `wrapper` as plain string properties; LLM ops change them; backend stores them; **`BindData` does NOT format**. The frontend renderer (later chunk) will read `content` + `format` + `wrapper` and produce the visible string + stylistic envelope. No backend formatter shipped this chunk. Vocabulary added to `domain.AtomFormat` (already existed since chunk 3) and new `domain.AtomWrapper`. Seeds (`component_price_rating.json`) gained realistic `format` values (`currency`, `stars-compact`); `component_brand_badge.json` already had `wrapper:"badge"`. New test file `format_wrapper_test.go` asserts BindData preserves these properties without coercing or stripping them, including the edge case where binding fails (Missing record) but format/wrapper survive intact for the LLM's next turn.

**Step 4 — docs**: known-gaps closed two rows (image-fill, nested-ref `reusable` as new "Грабля #2") and added two new ones (format/wrapper rendering tracked to frontend renderer port; the cache-threshold requirement surfaced by step 5). `v5-engine-plan.md` chunk 6 split into 6a (Anthropic shell + token measurement infra), 6b (prompt-builder + first LLM turn — with the hard cache-threshold gate), 6c (HTTP server + DI), 6d (tx fix for `zoneWriteWithDelta` + retry for `AddDelta` + tracer port). Subsequent items renumbered.

**Step 5 — token measurement**: built `internal/engine/tokens/` with V4 prompt + tool def copied verbatim from `project_v4/...` and a hand-written V5 sketch. Custom `count_tokens` HTTP wrapper (avoids pulling Anthropic SDK before chunk 6a). Test runs under build tag `tokens`, gated on `ANTHROPIC_API_KEY`, never asserts pass/fail — produces numbers via `t.Logf`. Initial Vlad-flagged miss: my naive measurement only counted raw `input_tokens`, missing the prompt-cache economics. Re-extended to compute effective USD-µ over a 10-turn conversation, distinguishing cache-write (1.25×) and cache-read (0.10×) regimes, gated on a `stableCacheThreshold = 4500` (Vlad's V4-prod number — Anthropic docs cite 2048 for Haiku but real-world stable behaviour wants ≥ 4500).

**First measurement (Haiku 4.5, "show me 3 products" scenario)**:

| Metric | V4 | V5 | Delta |
|---|---:|---:|---|
| Per-turn input_tokens | 7235 | 3705 | −3530 (−48.8%) |
| Cacheable prefix (system+tools) | 6449 | 3001 | below 4500 threshold |
| 10-turn effective cost (USD-µ) | 21,725 | 37,050 | **+70.5% (V5 is more expensive)** |

The naive per-turn win flips to a real loss when prompt-caching economics enter the picture. Recorded as a HARD GATE on chunk 6b in `v5-engine-plan.md` and as a known-gaps row.

## Known gaps / caveats

All registered in `docs/v5-known-gaps.md`:

- **V5 prefix below stable cache threshold** — 3001 < 4500. HARD requirement on chunk 6b. The natural source of growth is porting V4's BUILDING / COMPOSING / MODIFYING examples + decision rules into the V5 prompt; we'll need that content anyway.
- **V5 prompt sketch is paper, not production** — the +70.5% cost number is a worst-case (fully naive sketch); the real number lands when chunk 6b ships a real prompt-builder.
- **Token test is opt-in** (build tag `tokens`) — never runs in CI; re-measure manually after each prompt change.
- **`tokens.CountInputTokens` is a stand-in** — uses raw HTTP. Chunk 6a should replace with Anthropic SDK or wrap behind a real port.
