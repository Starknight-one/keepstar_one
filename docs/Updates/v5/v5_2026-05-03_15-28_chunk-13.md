## Context

После чанков 9–12 V5 движок функционально готов, но дебажить его — мука:
- tail backend.log теряется на restart
- ручной SQL по `v5_chat_session_deltas` без spans / cost
- pipelineResponse.spans живёт только до закрытия вкладки

Всё это ломается на dev box и тем более не масштабируется на production
с несколькими тенантами и сотнями сессий. Cross-tenant Chats UI давно
лежал в `docs/v5-known-gaps.md` как gap. Чанк 13 закрывает её
production-ready: V5 пишет per-turn trace в Neon, Curator UI читает.

Заодно с прицелом на Railway — V5 движок скоро тоже едет туда, и
trace persistence должна работать с первого деплоя.

## Approach

### Part A — V5 backend trace persistence

- **New table `v5_chat_session_traces`** (migration `migrations_trace.go`)
  с FK на `v5_chat_sessions` (CASCADE on delete) + 3 индексa:
  - `(tenant_id, created_at DESC)` — для фильтра по tenant в Curator
  - `(session_id, created_at DESC)` — для chat detail timeline
  - partial `(status, created_at DESC) WHERE status='error'` —
    для «show me error turns»
- **TraceRow domain type** + **TracePort interface** + **TraceAdapter**
  с idempotent INSERT (`ON CONFLICT (session_id, request_id) DO NOTHING`).
- **Pipeline handler hook**: после `pipeline.Execute` возвращается,
  собираем TraceRow из in-memory SpanCollector + response, и
  фаер-энд-форгет goroutine записывает в Neon. Detached context с
  10s timeout — caller request ctx может быть уже cancelled. Ошибки
  логируются но никогда не пробрасываются юзеру.
- **Failed turns persist too** — operators must see error traces;
  они доминируют в debugging signal.
- **Identity = `request_id`** (генерируется в logging middleware на
  каждый HTTP запрос). Отдельный turn_id вводить не стали.

### Part B — Curator backend chats endpoints

- **Adapter `internal/adapters/v5_chats.go`**: 3 SELECT-only метода
  читающих `v5_chat_*` таблицы напрямую из shared Neon (Curator уже
  использует тот же DATABASE_URL).
  - `ListChats(filter)` — сессии across all tenants с aggregates
    (turn_count, total_cost, total_tokens, has_errors), фильтры
    tenant_slug-or-id / status (active = activity within 30 min) /
    free-text search.
  - `GetChatTimeline(sessionID)` — header + ordered turns (без
    full spans, чтобы payload не раздувался).
  - `GetChatTurn(sessionID, requestID)` — full turn detail incl.
    spans JSONB (для waterfall).
- **Handler `handler_chats.go`** + 3 роута под существующим session
  middleware:
  - `GET /curator/chats?tenant=&status=&q=&limit=&offset=`
  - `GET /curator/chats/{sessionId}`
  - `GET /curator/chats/{sessionId}/turns/{requestId}`

### Part C — Curator frontend

- **api.js extension**: `chatsApi.list / timeline / turn`.
- **`ChatsPage.jsx`** — таблица + фильтры (tenant input, status select,
  q-search) + load-more pagination (50 per page).
- **`ChatDetailPage.jsx`** — header card с aggregates + per-turn
  timeline + lazy-loaded SpansWaterfall (text-table «Gantt» с
  отступом по depth, attrs JSON dump). Click row → expand spans.
- **App.jsx** — 2 новых route + sidebar секция «Tracing» с NavLink
  на /chats.
- **CSS** — chats / chat-header / chat-turns / spans-table / badge
  стили в app.css в брендовой тёмной палитре.

### Railway readiness

- **V5 backend**: новая миграция запускается на boot существующим
  runner'ом (main.go добавлена строка `{"trace", pgClient.RunTraceMigrations}`).
  Никаких новых env vars. Существующий Dockerfile подхватит без
  изменений. Trace persistence — non-blocking, никогда не валит
  пайплайн.
- **Curator**: уже имеет multi-stage Dockerfile + frontend bundled
  в backend's static. Чанк 13 не ввёл новых env vars — те же
  DATABASE_URL / CURATOR_INTERNAL_KEY / ADMIN_BASE_URL /
  CURATOR_COOKIE_SECURE. Никаких railway.toml правок.
- **Cross-DB conflicts**: shared Neon, Curator никогда не пишет в
  v5_*. Read isolation на уровне приложения — pure SELECTs из
  `v5_chat_*` + JOIN с `catalog.tenants`.

## Known gaps after chunk 13

- **Trace retention / cron cleanup** — Neon хранит всё; TTL
  cleanup отложен до момента когда объём станет заметным.
- **Spans waterfall как SVG-Gantt** — текстовая таблица сейчас;
  визуальный Gantt — polish item.
- **Curator unit-test coverage** — Curator не имеет vitest setup; smoke
  = manual + npm run build.
- **Cross-DB edge case** — если Curator переедет на отдельный Neon,
  потребуется replication / CDC между V5 и Curator. Сегодня одна
  общая БД.
- **TurnID** — пока используем request_id как trace identity. Если
  фронт/бэк начнут вводить explicit turnId, добавим в схему.
- **Liked / cart visual state** на чате — не закрыт (P2 polish).
- **/debug/traces UI на V5 backend** — данные теперь в БД, можно в
  будущем chunk вернуть waterfall в V5 dev surface, переиспользуя
  тот же Curator schema.
