## Context

Chunks 9 + 10 closed P0-A (tool surface) + P0-B (render path). Buttons rendered but
clicks were a `console.log` no-op — no /actions endpoint, no drill-down, no back, no
prefetch. V5 was a write-once read-only widget. Chunk 11 closes P0-C items 7-11 from
`docs/v5-engine-plan.md` and unblocks the prod-swap path: like/cart actions persist via
backend, card click drills to detail instantly via 1-level prefetch, back-button
restores prior view from a snapshot stack.

Architectural framing locked in this chunk: shop-layer (action handlers + adjacency
map) ≠ chat-layer (LLM picks visual shape). The closed action vocab (9 kinds) and the
adjacency map are stationary backend knowledge; LLM never picks an action kind or a
drill target.

## Approach

### Backend
- **`domain.UserActionKind`** (new file `internal/domain/user_action.go`): enum
  of 9 kinds (`like`/`unlike`/`cart_add`/`cart_remove`/`drill_detail`/`back`/
  `open_category`/`external_link`/`search`) + `UserAction` payload struct.
  Uses existing `EntityRef`. Renamed from the planned `Action` to avoid
  collision with the existing delta-side `domain.Action`.
- **`domain.TemplatePresetInUseKey`**: synthetic `"__presetInUse"` marker
  stamped on the marshaled Document map by `tool_visual_assembly` after
  the preset path runs. Read by the orchestrator + `/navigation/expand` to
  look up the drill target. Avoids extra zone-writes / schema churn.
- **`engine.InjectDefaultActions`** (new file `internal/engine/inject_actions.go`):
  walks Document, finds replicate clones (carry `__templateOrigin`) +
  single-entity detail subtrees, locates an empty frame `id="actions"`, and
  appends a like (♥) + cart_add (+) button atom bound to the resolved entity.
  Idempotent: a non-empty `actions` frame is left untouched (LLM-explicit
  actions win). Hook called at the end of `tool_visual_assembly.Execute`.
- **Seed updates**: added an empty `actions` frame to `product_card_compact`,
  `product_card_horizontal`, `product_card_list_row`, `product_detail`,
  `product_detail_horizontal` so InjectDefaultActions has a hook in every
  card / detail.
- **`POST /api/v1/actions`** (new `internal/handlers/handler_action.go`):
  handles like/unlike/cart_add/cart_remove. Mutates `state.Actions` via
  the existing `UpdateActions` zone-write. Rejects unknown / client-handled
  kinds with 400. `?sync=true` query param skips body for V4-style fire-and-forget.
- **`POST /api/v1/navigation/expand` + `/back`** (new `internal/handlers/handler_navigation.go`):
  expand pushes a `ViewSnapshot{Mode, Focused, Refs, Step, Template,
  PresetInUse, CreatedAt}` to the stack, materialises the drill-target
  preset against ONE entity (Materialise → ResolveAndInline → BindData →
  InjectDefaultActions), updates view + template zones. Back pops, restores
  view + template from the snapshot. ViewSnapshot got two new optional
  fields: `Template` (for restore-without-rerender) and `PresetInUse`
  (for adjacency lookup after restore).
- **`presets.SystemAdjacency`** (new `internal/engine/presets/adjacency.go`):
  hardcoded source-preset → drill-target map (`product_card*` → `product_detail*`).
  Single 4-row map today; lifts to `v5_presets.metadata` JSONB when the canvas
  microservice ships.
- **`PrefetchBuilder`** (new `internal/usecases/prefetch.go`): after Agent2
  returns, the orchestrator reads `__presetInUse` from the marshaled doc,
  looks up `SystemAdjacency`, materialises the drill-target preset (no
  replicate, no BindData — frontend binds on click), and packages it with
  the raw entity list as `PrefetchPayload{adjacentTemplate: {product: doc},
  entities: {product: [...]}}`.
- **Pipeline response**: `pipelineResponse.Prefetch` field exposed on the
  wire (`prefetch?: {...}`). Omitted when nil.
- **Routes**: 3 new routes wired in `internal/handlers/routes.go`.
- **Pipeline orchestrator constructor**: `NewPipelineExecute` signature
  extended with `state` + `prefetch` deps; `cmd/server/main.go` and the live
  test build the new graph.
- **Agent2 tool filter** (small fix surfaced by live test): Agent2 was
  calling `registry.GetDefinitions()` which returned ALL tools including
  Agent1's `catalog_search`. Occasionally the LLM picked catalog_search
  over visual_assembly, leaving the render step a no-op. Filtered Agent2's
  tools to only `visual_assembly` (mirrors V4 + Agent1 prefix-filter pattern).

### Frontend (`project_v5/frontend/`)
- **`api/actions.js`**: `postAction`, `expandView`, `goBack` (POST helpers
  with X-Tenant-Slug + Content-Type).
- **`renderer/RenderContext.js`**: React Context carrying
  `{apiBaseUrl, tenantSlug, sessionId, prefetch, onUpdateDocument, onSearch}`
  to every renderer leaf without prop-drilling.
- **`renderer/fillTemplate.js`**: port of V4 `fillFormation` for the
  scene-graph shape. Walks template, fills `fieldBinding` leaves, returns
  a `structuredClone` (does not mutate prefetch cache). Skips
  `__resolvedFrom` subtrees (forward-compat for already-bound components).
- **`renderer/actionDispatch.js`**: switch on `action.kind`. Backend kinds
  → `postAction`. `drill_detail` → optimistic local fill via prefetch +
  background `/navigation/expand` sync; cold-path waits for backend doc.
  `back` → `/navigation/back`. `external_link` → `window.open(_blank, noopener)`.
  `search` / `open_category` → `ctx.onSearch`.
- **`renderer/wrapper.js`**: button + link onClick now read `node.action`
  and dispatch through `useRenderContext()`. Buttons without action prop
  log a diagnostic. Buttons stopPropagation so card-body clicks don't fire.
- **`renderer/nodes/Frame.jsx`**: replicate clones (frames with
  `__templateOrigin`) get an `onClick` + `onKeyDown` (Enter / Space) that
  fires `drill_detail` for the entity matching the clone's `dataIndex`.
  Adds `kw-frame--clickable` class for cursor + hover styling.
- **`WidgetApp.jsx`**: new state for `prefetchRef` + `canGoBack` + chat
  input ref. Stores prefetch on each pipeline response. Wraps the
  scene-graph in `RenderContext.Provider`. Renders a back button when
  `canGoBack`. `dispatchAction` updates document + flips canGoBack.
- **`ChatPanel.jsx`**: optional `inputRef` parent prop — exposes a
  `setValue(v)` handle the search action handler uses to pre-fill the
  input.
- **`widget.css`**: `.kw-back` (outline → filled hover) + `.kw-frame--clickable`
  (translateY -2px on hover, brand-blue shadow).

## Known gaps / caveats

- **Visual-quality of cards still bad** — 4 render-quality gaps from the first
  manual test on 2026-05-03 still open (no grid layout, tenant field name
  mismatch, no size, modify-bias). Chunk 12.
- **Cross-tenant chat inspection in Curator** still needed. Chunk 13.
- **Liked / in-cart visual state** — buttons fire backend correctly but the
  rendered card doesn't change visually after click (no filled heart, no cart
  count badge). P2 polish item.
- **Back button UI** ships in this chunk as `.kw-back` above the document; a
  proper breadcrumb / stepper is a chunk-12 polish item.
- **`open_category` and `search`** dispatch handlers wired but no preset emits
  them yet. Will activate when category presets land.
- **Adjacency in DB**: `SystemAdjacency` is a 4-row Go map. Lifts to
  `v5_presets.metadata` JSONB when the canvas microservice ships.
- **Agent2 catalog_search regression**: the filter we added is the right fix
  but should be considered when introducing additional Agent2-only tools in
  the future — extend the filter then. Same model as Agent1's prefix filter.
- **InjectDefaultActions edge case**: only fires when an empty `actions`
  frame exists. Freestyle LLM cards without that frame won't get default
  actions. The system seeds all carry it now.
