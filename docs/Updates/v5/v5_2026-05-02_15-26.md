## Context

V5 takes v9's TypeScript scene-graph engine as foundation and ports it to Go. V4 has a structural ceiling (3-level Formation/Widget/Atom) that no applier rewrite lifts; on prompts like "draw a product landing", V4 vs v9 output is dramatically different. V4 stays in `project_v4/` as production until V5 is ready to swap in.

This is **chunk 1 of the V5 plan** — the engine package alone. State, delta-stream, binding layer, presets, pipeline integration are subsequent chunks. Goal of this chunk: a Go package where I can build a Document programmatically, apply Insert/Update/Override/Move/Delete commands via `CommandHistory`, expand RefNodes with descendants overrides, and resolve `$variable` references — covered by tests. No HTTP, no DB, no LLM yet.

Plan reference: `~/.claude/plans/spicy-dreaming-waffle.md` (not committed).

## Approach

Faithful port of v9's `packages/domain` (~1319 lines TS, 24 files) to Go. Engine operates on `Node = map[string]any` (Option A from the plan): TS treats nodes as duck-typed objects, so the most direct Go port uses the same property-bag representation. Typed wrappers will be added at the layer above (chunk 2 — domain), but the engine itself stays generic.

Per-file mapping:

- v9 `entities/nodes.ts` → `node_types.go` (constants for the 13 node types; `Node` alias; predicates `HasChildren`/`HasGraphics`/`IsRef`; `Children`/`SetChildren` helpers that normalize across `[]Node` and `[]any` shapes from JSON)
- v9 `entities/document.ts` → `document.go` (`Document` struct with typed top-level + `Children []Node`; `VariableDef` tagged by `Type`; `NewDocument()`)
- v9 `value-objects/*.ts` → `value_color.go` / `value_position.go` / `value_layout.go` / `value_fill.go` / `value_stroke.go` / `value_effect.go` / `value_text_style.go` (parse helpers + sizing/padding normalizers + AsBool/AsNumber/AsString unwrappers for `*OrVariable` unions)
- v9 `operations/*.ts` → `command.go` + `op_insert.go` / `op_update.go` / `op_override.go` (both SetOverride and SetRootOverride) / `op_move.go` / `op_delete.go`. `Command` interface returns `error`; `CommandHistory` tracks undo/redo with the v9 "redo cleared on new execute" rule.
- v9 `services/*.ts` → `id_generator.go` (5-char alphanumeric, math/rand) / `scene_graph.go` (FindNodeByID, FindParent, WalkNodes, FindReusableNodes, FindNodesByType, FindRefsToNode, FindSlots — does not recurse into RefNode children, matching v9) / `variable_resolver.go` (ResolveColor/Number/Boolean/String + theme matching + magenta/0/true/"" fallbacks + single-level chained variable resolution) / `component_resolver.go` (Expand with deep clone via `cloneAny`/`cloneNode` helpers; root + descendants overrides; slot injection via `descendants[slotID].children`; max depth 10 for circular ref protection)

## Verification

```
cd project_v5/backend
go build ./...                       # exit 0
go test ./internal/engine/... -v     # all pass
```

Smoke test covered (`smoke_test.go`):
1. Build a reusable Button component (Frame containing Rect + Text).
2. Insert a RefNode pointing to the button, with `descendants` overriding the label.
3. Run `ComponentResolver.Expand` → expanded tree's label content is the override.
4. Apply an `UpdateCommand` on the resolved tree's text.
5. Undo → text reverts to the override value.

Total runtime ~0.4s.

## Known gaps / caveats

- **No JSON wire compatibility with v9 tested yet.** Round-trip Marshal/Unmarshal works internally, but exact-shape compatibility with v9's TS marshaling (e.g. omitting falsy values) is not verified. Will matter for Stream B when canvas exports presets the engine reads back. Defer to chunk 2.
- **`Node` is `map[string]any`** — engine has no compile-time field validation. Accept this trade per plan; typed wrappers will live in `internal/domain` (chunk 2).
- **`id_generator`** uses `math/rand` (not crypto-grade). Caller responsible for collision handling — matches v9.
- **`MoveCommand.Undo`** falls back to document root if the original parent has been deleted — slight drift from v9, which doesn't have this fallback. Deliberate: a deleted-parent state is unrecoverable and "drop at root" is a safer default than silently losing the node.
- **No state, no delta-stream, no binding layer, no LLM, no HTTP** — deferred to chunks 2-7 per `docs/v5-engine-plan.md`.
- **No layout engine.** v9's `packages/layout` (Yoga WASM) is intentionally out of scope; per plan, layout runs browser-side.
