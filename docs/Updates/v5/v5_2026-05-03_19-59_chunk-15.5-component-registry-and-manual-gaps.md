## Hotfix — SystemComponentRegistry (commit bcb47b5)

Chunk-9 сделал `SystemPresetRegistry` (in-process fallback для 7 system
пресетов), но **забыл аналог для компонентов**. Reusable subtrees
(`price-rating-root`, `brand-badge-root`) embedded как
`ComponentPriceRatingJSON` / `ComponentBrandBadgeJSON` (chunk 5),
но в runtime никуда не подавались. DB `v5_components` = 0 строк → 
`ListPublishedComponents` возвращал [] → `Materialise(preset, [])` →
refs unresolved.

Fix:
- `presets.SystemComponentSeeds` — map `name → []byte`. Зарегистрированы
  оба component JSON под именами совпадающими с top-level node id
  (которые `FindNodeByID` ищет при `expandRef`).
- `presets.SystemComponentRegistry` — mirror of SystemPresetRegistry:
  sync.Map cache, validate-on-first-use, List for union.
- `domain.Component.IsSystem bool` — mirror Preset.IsSystem.
- `postgres.NewComponentAdapterWithSystem(client, registry)` —
  fallback in `GetPublishedComponent` (на `pgx.ErrNoRows`) + union в
  `ListPublishedComponents` (DB rows win).
- `cmd/server/main.go` — wire registry в production-adapter.

Verification (after Railway redeploy):
- curl `/api/v1/pipeline {query:"тонер"}` →
  - 3 cards с binding'ом полным: image (`fill+`), title (bound),
    **price** ("1 890 ₽" bound), **rating** (where present in DB),
    **brand badge** ("Dear, Klairs" bound)
- latencyMs 2141ms, cost $0.014 (cold cache на новом deploy)
